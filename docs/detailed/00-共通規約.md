# 00: 共通規約（`src/jevfwd/common/`、全モジュール）

- 対象：`common/timeutil.py` `common/codes.py` `common/hashing.py` `common/jsonutil.py` `common/errors.py` `common/logutil.py` `common/versions.py`、および全モジュールが守る規約
- マイルストーン：M1（以降のすべてのモジュールが前提にする）
- 関連：CLAUDE.md「コーディング規約」「絶対ルール」1・5・6、基本設計 2章、ADR 002・004・014・020・021
- 版：2026-09-20 初版

## 1. 責務

- 時刻・証券コード・JSON 正規化・ハッシュ・例外・ログのマスクを**一か所**に置き、各モジュールが同じ書式を使うようにする
- モジュール境界（誰が誰を import してよいか）を表で固定し、テストで担保する
- テストの書き方（fixture、DB、モック、ID）を固定し、`docs/detailed/` の受入テスト表がそのまま写せるようにする

`common` は業務判断を持たない。設定も読まない（`settings.py` が読む）。

## 2. 依存

標準ライブラリのみ。`zoneinfo`（3.9+）で JST。外部ライブラリは `common` から import しない。

## 3. 時刻

| 規則 | 内容 |
|---|---|
| 保存 | UTC。文字列 `YYYY-MM-DDTHH:MM:SS+00:00`（`datetime.isoformat(timespec="seconds")` の出力）。秒精度。`Z` は使わない。ミリ秒は持たない（`latency_ms` は整数列） |
| 順序 | 上記書式は文字列比較が時系列順になる。SQL の `ORDER BY ts`、`WHERE published_at >= ?` はそのまま使える |
| 公表時刻 | TDnet は分単位。`published_at` は秒 `00`。JST の `HH:MM` と暦日から `jst_minute_to_utc_str(date, "17:30")` で作る |
| 日付列 | `ledger.day` `prices.date` `listed_master.as_of` `outcomes.entry_date` などは **JST の暦日** `YYYY-MM-DD`（市場の営業日で意味を持つ） |
| 表示 | JST は表示・通知・ダイジェストのみ。`to_jst(dt)` で変換し `format_jst(dt)` = `YYYY-MM-DD HH:MM JST` |
| 現在時刻 | `now_utc()` を使う。判定・束ねの関数は `now: datetime` を**引数で受ける**（テストで固定。`datetime.now` を関数内で呼ばない） |
| naive | `datetime` に tzinfo が無ければ `ValueError`。黙って UTC 扱いしない |
| state の JSON | Jev に渡す `published_at` は JST の `+09:00` 表記でよい（基本設計 3.3 の例）。DB の書式と混同しない |

```python
UTC_FMT_GLOB = "[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]T[0-9][0-9]:[0-9][0-9]:[0-9][0-9]+00:00"   # DDL の CHECK と同じ
JST = ZoneInfo("Asia/Tokyo")

def now_utc() -> datetime                                  # tz=UTC、マイクロ秒は 0 に丸める
def to_utc_str(dt: datetime) -> str                        # naive → ValueError。他 tz は UTC に変換
def parse_utc(s: str) -> datetime                          # 書式違反は ValueError
def to_jst(dt: datetime) -> datetime
def format_jst(dt: datetime) -> str                        # "2026-09-17 17:30 JST"
def jst_minute_to_utc_str(day: date, hhmm: str) -> str     # ("2026-09-17", "17:30") → "2026-09-17T08:30:00+00:00"
def jst_day(dt: datetime) -> str                           # JST 暦日 "YYYY-MM-DD"
def is_utc_str(s: str) -> bool
```

## 4. 証券コード

- DB の `code` は **TDnet 一覧の5文字**をそのまま（`35600` `590A0` `13264`）。5文字目は銘柄種別を持つ（`0`=普通株、`4`=ETF 等。`tests/fixtures/tdnet_list_2026-09-14_16.tsv` で確認）ので落とさない。DDL は `length(code) = 5`
- J-Quants も5文字なので変換不要
- Jev の state・問いの主語・ダイジェスト表示は4文字（`3560`）。`display_code(code5)`：5文字目が `0` なら先頭4文字、それ以外（`13264`）はそのまま5文字を返す（除外対象なので通常は判定に乗らない）
- fixture の本文（`3560_hobonichi_…`）や ADR の記述にある4桁は表示コード。テストで DB に入れるときは `"35600"` のように5文字にする

```python
def validate_tdnet_code(code: str) -> str      # 5文字・英数字大文字でなければ ValueError。そのまま返す
def display_code(code5: str) -> str            # "35600" → "3560", "590A0" → "590A", "13264" → "13264"
```

## 5. JSON・ハッシュ・版

- `canonical(obj) -> str`：`json.dumps(obj, ensure_ascii=False, sort_keys=True, separators=(",", ":"))`。`*_json` 列はこれで作る。`float` は Python の `repr`（`json` 既定）
- **生保存**する列（正規化しない）：`judgments.request_json` `judgments.response_json` `question_versions.json` `state_versions.spec`。受け取った文字列を1バイトも変えない
- `sha256_hex(data: bytes) -> str`、`sha256_file(path) -> str`：16進小文字64桁。版ファイルの SHA はバイト列に対して取る（ADR 020 の値と一致）
- `version_from_filename(path, stem) -> str`：`questions.v2.json` → `"v2"`。正規表現 `^<stem>\.(v\d+)\.(json|yaml)$`。合わなければ `ConfigError`
- 版文字列は `v` ＋ 正の整数（`v1` `v2`）。比較は数値で

## 6. 例外

```python
class JevfwdError(Exception): ...            # 全例外の基底。CLI は exit 1
class ConfigError(JevfwdError): ...          # 設定・版ファイル・秘密
class StoreError(JevfwdError): ...           # DB 層（トリガー欠落、マイグレーション不整合）
class SchemaMismatchError(StoreError): ...   # schema_version 不一致。CLI は exit 3
class FetchError(JevfwdError): ...           # M2
class JudgeError(JevfwdError): ...           # M4（未凍結版、API 失敗の集約）
```

- `sqlite3.IntegrityError` `sqlite3.OperationalError` は包まない（どの制約に当たったかをメッセージで残すため）
- **失敗は行として記録する**（CLAUDE.md）。取得失敗は `events.pdf_status='failed'`、判定失敗は `judgments.error_type`。例外を投げて終わりにしない。プロセスの最上位ループで捕まえ、`heartbeat(ok=0, note=<型と要旨>)` を書いて次周期へ
- メッセージは日本語でよい。秘密の値を含めない

## 7. ロギング

- stdlib `logging`、stdout のみ（Docker logs が拾う）。書式 `%(asctime)s %(levelname)s %(name)s %(message)s`、`converter=time.gmtime`（UTC）、`datefmt="%Y-%m-%dT%H:%M:%S+00:00"`
- ロガー名はモジュール名（`logging.getLogger(__name__)`）
- `common/logutil.py`：
  - `setup_logging(level: str, secrets: Iterable[str]) -> None`：ルートロガーにハンドラと `SecretMaskFilter` を付ける。2回呼んでも重複しない
  - `SecretMaskFilter(logging.Filter)`：`record.getMessage()` に秘密の値（`Secrets.values()`）が含まれていたら `***` に置換して `record.msg` を書き換え、`record.args=None` にする。空文字・4文字未満の値はマスク対象にしない（誤爆防止）
- `Secrets` は `repr` でマスク済み（02-設定）。それでも `logger.debug("%r", secrets)` 以外で値を文字列化しない

## 9. 設定と秘密

- 周期・閾値・パスは `config/settings.yaml`（02-設定）。コードに数値を直書きしない。例外：DB の PRAGMA 値と `busy_timeout`（01-凍結ログ 6章。変更は ADR）
- 秘密は環境変数のみ。`os.environ` を直接読むのは `settings.Secrets.from_env` と `resolve_settings_path` だけ。他のモジュールは `Secrets` を引数で受ける
- `.env` はコードで読まない。ローカルは `set -a; source .env; set +a` の後に `python -m jevfwd.cli …`、Docker は compose の `env_file`

## 10. SQLite の前提

- 3.31 以上（ローカル WSL 3.31.1、Docker `python:3.11-slim`/bookworm 3.40）。使わない構文：`RETURNING`（3.35）、`STRICT`（3.37）、`->`/`->>`（3.38）、`json_*` 関数（環境依存）。テスト T00-13 が `src/` を grep する
- 書き込みは `db.transaction()`（`BEGIN IMMEDIATE`）の中でだけ。`INSERT OR REPLACE` `INSERT OR IGNORE` `ON CONFLICT` は使わない
- WAL は同一ホストのローカル FS のみ。NFS/CIFS 上のファイルを開かない。NAS のバックアップは `sqlite3 .backup` の出力を rsync し、検証は NAS 側で開く

## 11. 訂正の作法（追記専用の下で）

- 凍結テーブルの行は直さない（トリガーで直せない）。誤りは新しい行で表す：`bundles` は `supersedes_id`、`judgments` は `purpose` と新しい行、`events` は新しい PDF 取得
- 「現在の bundle」は `queries.current_bundle`。主分析・ダイジェスト・採点は superseded な bundle を使わない
- 採点系（`prices` `outcomes` 等）も UPDATE しない。再計算は `scored_at` / `source_version` を変えた新行

## 12. コード規約

- Python 3.11+、型ヒント必須（`from __future__ import annotations` は使わず 3.11 構文）。`dataclass(frozen=True, slots=True)` を入力・値オブジェクトに使う。pydantic は設定ファイルの検証にだけ使う
- 1モジュール1責務、モジュール冒頭の docstring に責務を1〜3行。識別子は英語、コメント・ログ・例外メッセージは日本語でよい
- 外部 I/O（HTTP、ファイル、時刻）は関数の引数か薄いクライアントで受け、テストで差し替える。`datetime.now()` `os.environ` `httpx.get` を業務関数の中で直接呼ばない
- マジックナンバー禁止。設定（`settings.yaml`）か、根拠を添えた定数（`common` か当該モジュール冒頭）に置く
- `print` は `cli.py` の結果出力だけ。他は `logging`

## 13. テスト規約

- `pytest`、`tests/` 直下にフラットに置く（`tests/test_store.py` 等。00 → `tests/test_common.py` と `tests/test_conventions.py`）
- 受入テスト表の ID を docstring 1行目に書く。表にないテストを足すのは自由だが、表のテストを削る・弱めるときは詳細設計を先に直す
- DB は `tmp_path` のファイル。`:memory:` は WAL にならないので使わない。DB を要するテストは `db.migrate(tmp_path / "t.sqlite")` から始める
- 外部 I/O はモック（`httpx` はトランスポート差し替え、時刻は `now` 引数）。ネットワークに出るテストは書かない（契約テストは M4 で人が `--once` を手で実行）
- fixture は `tests/fixtures/` の実ファイル。受入テスト表に書いたファイル名が存在しないテストは書かない。fixture の追加は `tests/fixtures/README.md`（M2 で作る）に出典を書く
- 版ファイル（`config/questions.v*.json` `config/*.v*.yaml`）の SHA-256 定数をテストに置き、変更を検知する（ADR 020）
