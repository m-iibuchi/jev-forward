- 対象：`bundle/grouper.py` `bundle/filters.py` `bundle/runner.py`、`settings.Calendar`、`config/filters.v1.yaml`（追加分）、`config/trading_calendar.v1.yaml`

- 版：2026-09-20 初版（同日追補：`run_once` に `state_of` を注入、T04-35、★11。task 017）

## 1. 責務

- まだ束ねられていない `events` を見つけ、同一銘柄・同時刻の開示を1つの出来事（bundle）にまとめる
- 連番表題を1つの「論理開示」に束ね直す（ADR 016）
- 除外・重要度低下・TOB 例外を分類し、`bundle_role` `skip_reason` `flags_json` を決める（ADR 003・019・023）
- 主開示を選び、`session` を決める（ADR 011）
- `bundles` に1行 INSERT する

しないこと：本文の加工・切り詰め（05-state構築）、判定（07-判定）、市場データの参照（`bundle` は `market` を import しない。00-共通規約 8章）、`events` の書き換え（追記専用）。

判断のほとんどは純関数（`grouper.py` `filters.py`）に置き、DB に触るのは `runner.py` だけにする。`now` は必ず引数で受ける。

## 2. 依存

- 標準ライブラリのみ（`re` `json` `datetime` `dataclasses`）
- `jevfwd.common`（`timeutil` `codes` `jsonutil` `errors` `logutil`）、`jevfwd.settings`、`jevfwd.store`
- `market` `state` `judge` は import しない（00-共通規約 8章）。M3 のループを繋ぐのは `cli`

## 4. データ契約

### 4.1 仕掛かりの見つけ方（ADR 022）

`events.event_id` は `INTEGER PRIMARY KEY`（01-凍結ログ 4.2 ★1）なので採番は単調増加で、**到着順**と一致する。仕掛かりは event_id で追う。

- 起動時に一度だけ `low = (最小の未カバー event_id) - 1` を求める。範囲は `bundle.scan_lookback_sec`（既定 259200 = 3日）
- 以降は `event_id > low` を昇順に読み、確定した分だけ `low` を前へ進める（プロセス内）
- **時刻の窓で探さない**。`fetch.list_lookback_days` により前日分が後から入ることがあり、`published_at` の窓は追い越された行を永久に落とす
- coverage には **superseded な bundle も含める**。`queries.current_bundle` は分析用で、仕掛かり判定には使わない（含めないと再起動のたびに再束ねになる）
- `bundles` に一意制約は無いので、INSERT は `db.transaction()`（`BEGIN IMMEDIATE`）の中で coverage を読み直してから行う。二重起動時の重複 bundle を防ぐ唯一の砦

### 4.2 束ね窓と猶予

| 規則 | 値・内容 |
|---|---|
| アンカー | 未カバー events のうち、同一コードで **最小の `event_id`**（`published_at` は分単位で同着が多い） |
| メンバー | 同一コードで `abs(published_at - アンカーの published_at) <= bundle.window_sec`（既定 300 秒）。連鎖はしない（窓はアンカー基準で1回だけ張る） |
| 確定 | `now - アンカーの received_at >= bundle.grace_sec`（既定 120 秒）。`published_at` は分単位かつ取得遅れに引きずられるので使わない |
| 1周期の上限 | `bundle.max_per_cycle`（既定 200）。障害明けに数百件が一斉確定して判定費用が跳ねるのを抑える |
| 追いつき | `now - アンカーの published_at > bundle.grace_sec * bundle.catchup_factor`（既定 10）なら `flags` に `catchup`。`judgments.delayed` は負荷と障害を区別できないので、束ね側で別に残す |

### 4.3 論理開示（ADR 016）

- `filters.strip_sequence(title)` が **連番を返したときだけ**、連番を除いた表題が一致する events を1論理開示にまとめる
- 連番が無い同一表題は**別の論理開示**にする。リベルタ（`tdnet_list_2026-09-17.tsv` 72・73行目）は同一表題・同時刻の別契約で、まとめると ADR 004 の判断を壊す
- 連結順は `sequence_index` の昇順 → `published_at` → `event_id`。分割は到着順が前後する（中部電力は3件とも 08:00）
- `sequence_total` が食い違う（（１／３）と（２／４））ときは束ねず、`flags` に `sequence_mismatch` を付けて別の論理開示にする
- `logical_docs_json` は `[{"title": ..., "event_ids": [...]}, ...]`（`rank` は保存しない。`filters` の版が変われば再計算できる）

### 4.4 主開示の優先順

`config/filters.v1.yaml` の `primary_priority` を上から見て、最初に一致した位置を rank とする。どれにも一致しなければ `other` の rank。並べ替えの鍵は `(rank, published_at, event_id)` で全順序になる。

`bundles.primary_event_id` は主開示の論理開示の**先頭 event_id**。

### 4.5 除外・重要度低下・TOB の判定順序（ADR 019・023、task 014）

bundle 単位で上から評価し、最初に成立したものを採る。

| 順 | 判定 | 結果 |
|---|---|---|
| 1 | `filters.has_excluded_name_prefix(company)`（`Ｅ－` `Ｎ－` `Ｒ－` `Ｉ－`） | `excluded` / `excluded_instrument` |
| 2 | `filters.code_excluded(code)`（5文字目 4） | `excluded` / `excluded_instrument` |
| 3 | **すべての**論理開示が `filters.title_excluded(title)` | `excluded` / `excluded_title` |
| 4 | `listed_master`（整理・監理、上場後60日未満） | `excluded` / `excluded_supervised` `excluded_new_listing`。**段階1では判定しない**（4.6） |
| 5 | TOB 判定（4.7） | `tob_primary` / `tob_attached`、または `normal` + `tob_buyer` |
| 6 | いずれかの論理開示が `filters.title_low_priority(title)` | `normal` のまま `flags` に `low_priority:<key>` |

3 は論理開示単位で見る。一部だけ一致する場合は除外しない（同時刻に約款変更と別の開示が並ぶことがある）。

### 4.6 段階1で判定できない除外（task 014 の結論）

`market_cache.enabled: false` の間は `listed_master` が無く、**整理・監理銘柄と上場後60日未満は除外されない**。これを許容する。理由と後始末：

- 判定・凍結は行われるので、採点時に `listed_master` を突き合わせて母集団から落とせる（凍結ログは残る）
- 主検証の抽出条件に「`listed_master` で整理・監理・上場60日未満でないこと」を加える（10-採点、`docs/事前宣言.md`）
- 実例：`8894_revolution_3bundle.txt`（特別注意銘柄）は段階1では `normal` として判定される
- コードによる ETF 除外も穴がある。`tdnet_list_2026-09-17.tsv` 92〜96行目の `13690 Ｏｎｅ・日経２２５` 等は社名接頭辞（`Ｅ－` でない）にもコード（末尾 0）にも掛からず、`exclude_titles` の「投資信託約款の変更」だけが拾う。表題が違えば漏れる。段階2までに `listed_master` を入れる

### 4.7 TOB 例外（ADR 003 を ADR 023 で補足）

ADR 003 の根拠は「**対象銘柄**の株価は買付価格でほぼ決まるので、同時刻の悪材料が効かない」こと。買付者側には当てはまらない。

| 条件 | 扱い |
|---|---|
| `tob_exclude_titles` に一致（例：「公開買付けに準ずる行為」） | TOB ではない。通常どおり |
| `tob_target_titles` に一致（「当社株券等に対する公開買付」「賛同の意見表明」「応募推奨」） | その論理開示を `tob_primary` の単独 bundle、同時刻の残りを `tob_attached` の別 bundle |
| `tob_titles` に一致するが対象者側でない（買付者側。「（証券コード：NNNN）に対する公開買付けの開始」） | 束ねは通常どおり。`bundle_role='normal'` のまま `flags` に `tob_buyer` |

fixture での確認（`tdnet_list_2026-09-17.tsv`）：

- 80行目 `68900 フェローテック`「株式会社日本抵抗器製作所（証券コード：6977）に対する公開買付けの開始に関するお知らせ」→ 買付者側。`normal` + `tob_buyer`
- 82行目 `69770 日抵抗器`「株式会社フェローテックによる当社株式に対する公開買付けに関する賛同の表明及び応募推奨のお知らせ」→ 対象者側。`tob_primary`
- 30行目 `44360 Ｇ－ミンカブ`「公開買付けに準ずる行為として政令で定める買い集め行為に関するお知らせ」→ 除外パターン。同時刻8件の資本業務提携が `tob_attached` に落ちるのを防ぐ
- `tdnet_list_2026-09-14_16.tsv` 366行目 `88480 レオパレス２１` → 対象者側。367・370行目（無配・事業譲渡）が `tob_attached`

対象者側の論理開示が複数あるときは、それらをまとめて1つの `tob_primary` bundle にする（同じ案件の意見表明と添付）。

### 4.8 暫定判定と本判定（ADR 015 を ADR 024 で補足、task 013）

`events` は追記専用なので、表題だけで登録した行に後から本文を足せない。PDF が後から取れた場合は**新しい event 行**になり、その行は未カバーとして現れる。

- その event が既存 bundle の窓に入り、かつ同一表題（`strip_sequence` 後）なら、全 event を含む**新しい bundle** を `supersedes_id=<旧 bundle_id>` で作る
- 新 bundle は本文つきで state を組み直し、`purpose='full'` で判定する。旧 bundle の `provisional` 判定は残る
- したがって「full の state」は superseding bundle の `state_json` にある（task 013 の選択肢3の穴が埋まる）
- 旧 bundle の `flags` は引き継ぎ、新 bundle に `supersedes:provisional` を足す

### 4.9 supersede の歯止め（ADR 022）

追記専用なので、作り直しが止まらないと行が無限に増える。次の全部を満たすときだけ superseding bundle を作る。

1. **集合が変わること**：新しい event 集合が既存 bundle の集合と**一致しない**（一致したら作らない。再起動時の無限ループを止める最後の砦）
2. **意味が変わること**：(a) 論理開示が完成する（連番の欠けが埋まる）、(b) `primary_event_id` が変わる、(c) `bundle_role` / `skip_reason` が変わる、のいずれか。どれでもなければ独立した bundle にして `flags` に `late_arrival`
3. **期限内であること**：`now - アンカーの published_at <= bundle.supersede_deadline_sec`（既定 3600）。過ぎたら独立 bundle
4. **深さの上限**：`bundle.max_supersede_depth`（既定 2）。超えたら独立 bundle ＋ `flags` に `supersede_capped` ＋ WARN ログ
5. **判定済みなら慎重に**：その bundle に `purpose='full'` の judgment が既にあるときは 2 の (b)(c) のときだけ作り直す（superseded な bundle は主検証から落ちるので、判定費用が無駄になる）

### 4.10 `session` の判定（ADR 011）

JST に直してから、上から順に評価する。非営業日を先に見る（でないと土曜 08:30 が `pre_open` になる）。

```
1. calendar.is_business_day(jst_day) が False        → after_close
2. jst_time >= calendar.close_time(jst_day)          → after_close    # 通常 15:00、半日立会 11:30
3. market.pre_open_from <= jst_time < market.session_open  → pre_open  # 08:00〜08:59:59
4. market.session_open <= jst_time < close_time      → intraday
5. jst_time < market.pre_open_from                   → after_close    # 前営業日の引け後の続き
```

`session` はエントリーする営業日を持たない。採点側で `calendar.next_business_day(jst_day(anchor))` として求める（10-採点。列を増やさない）。

### 4.11 `flags_json` の語彙（ADR 019）

文字列の配列。M3 で確定する全一覧：

| flag | 意味 | 付ける場所 |
|---|---|---|
| `low_priority:<key>` | 重要度低下（`growth_plan` `cg_report`） | 04 |
| `tob_buyer` | 公開買付けの買付者側（4.7） | 04 |
| `late_arrival` | 窓に遅れて来た event の独立 bundle | 04 |
| `supersedes:provisional` | 暫定判定の bundle を作り直した | 04 |
| `supersede_capped` | 作り直しの上限に達した | 04 |
| `sequence_mismatch` | 連番の分母が食い違う | 04 |
| `catchup` | 障害明けの一斉確定（4.2） | 04 |
| `filters:vN` `calendar:vN` | どの版の規則で分類したか | 04 |

## 5. エラー時の振る舞い

| 事象 | 振る舞い |
|---|---|
| INSERT 直前の再チェックで既にカバー済み | その計画を捨てて INFO ログ。例外にしない（二重起動の正常な帰結） |
| `sqlite3.IntegrityError`（CHECK / FK） | 握りつぶさず伝播。`runner` の呼び出し元（`cli`）が捕まえて `heartbeat(ok=0, note=...)` |
| `state_of(plan)` が `JevfwdError`（切り詰め不収束、schema 不一致、社名空） | bundle 行は作る（state 列 NULL、`flags` に `state_error:<例外クラス名>`）。WARN ログ。判定側（07-判定）は `state_json IS NULL AND bundle_role <> 'excluded'` の bundle に `judgments` のエラー行を残す（task 017） |
| `state_of(plan)` が `JevfwdError` 以外の例外 | 伝播（実装の誤り）。`cli` が捕まえて `heartbeat(ok=0)`、その周期の plan は次周期にやり直し（未 INSERT なので再計画される） |
| カレンダーの収録年外 | `ConfigError`。起動時に「今日と翌30日が収録されているか」を検査して早く落とす |
| `grace_sec + 600 秒`を過ぎても未カバーの event が残る | `heartbeat(ok=0, note='bundler stuck: event_id=...')`。滞留は障害であって順番待ちではない |
| supersede の上限超過 | 独立 bundle にして WARN。例外にしない |
| `queue_depth` | このプロセスでは「未カバー event の件数」を `heartbeat.queue_depth` に書く（DDL にある列の持ち主を決める） |

```python
# grouper.py
def plan_bundles(events, coverage, now, cfg, filters, calendar):
    uncovered = [e for e in events if e.event_id not in coverage.covered]
    plans, used = [], set()
    for anchor in uncovered:                                  # event_id 昇順
        if anchor.event_id in used:
            continue
        t0 = parse_utc(anchor.published_at)
        members = [e for e in uncovered
                   if e.code == anchor.code and e.event_id not in used
                   and abs((parse_utc(e.published_at) - t0).total_seconds()) <= cfg.bundle.window_sec]
        if (now - parse_utc(anchor.received_at)).total_seconds() < cfg.bundle.grace_sec:
            continue                                          # 猶予中。次の周期へ
        prev = _overlapping_bundle(coverage, anchor, cfg)     # 4.9 の歯止めを全部通す
        if prev is not None:
            members += [e for e in events if e.event_id in prev.event_ids]
        docs = logical_docs_of(members, filters)
        role, skip, flags = classify(docs, {e.event_id: e for e in members}, filters)
        if prev is None or _supersede_allowed(prev, members, role, skip, cfg, now):
            plans.append(BundlePlan(
                code=anchor.code, company=next((e.company for e in members if e.company), None),
                anchor_published_at=anchor.published_at,
                session=session_of(anchor.published_at, cfg.market, calendar),
                primary_event_id=primary_of(docs, {e.event_id: e for e in members}),
                event_ids=tuple(sorted(e.event_id for e in members)),
                logical_docs=docs, bundle_role=role, skip_reason=skip,
                flags=flags + _version_flags(cfg) + _catchup_flag(anchor, now, cfg),
                supersedes_id=(prev.bundle_id if prev else None)))
            used.update(e.event_id for e in members)
        if len(plans) >= cfg.bundle.max_per_cycle:
            break
    return plans

def logical_docs_of(events, filters):
    groups: dict[tuple[str, int | None], list[EventView]] = {}
    for e in events:
        stripped, matched = filters.strip_sequence(e.title)
        key = (stripped, sequence_total(matched)) if matched else (e.title, e.event_id)   # 連番が無ければ1件1論理開示
        groups.setdefault(key, []).append(e)
    docs = []
    for (title, _), members in groups.items():
        members.sort(key=lambda e: (sequence_index(filters.strip_sequence(e.title)[1]) or 0,
                                    e.published_at, e.event_id))
        docs.append(LogicalDoc(title=title, event_ids=tuple(m.event_id for m in members),
                               rank=filters.primary_rank(title)))
    return tuple(docs)

def session_of(anchor, market, calendar):
    jst = to_jst(parse_utc(anchor)); day, t = jst.date(), jst.time()
    if not calendar.is_business_day(day):        return "after_close"
    if t >= calendar.close_time(day):            return "after_close"
    if _hhmm(market.pre_open_from) <= t < _hhmm(market.session_open):  return "pre_open"
    if _hhmm(market.session_open) <= t:          return "intraday"
    return "after_close"

# filters.py（settings.Filters のヘルパを組み合わせる層。設定は読まない）
def classify(docs, events, filters):
    company = next((e.company for e in events.values() if e.company), "") or ""
    code = next(iter(events.values())).code
    if filters.has_excluded_name_prefix(company):   return "excluded", "excluded_instrument", ()
    if filters.code_excluded(code):                 return "excluded", "excluded_instrument", ()
    if docs and all(filters.title_excluded(d.title) for d in docs):
        return "excluded", "excluded_title", ()
    # listed_master（整理・監理・上場60日未満）は M6。段階1は判定しない（4.6）
    flags = tuple(f"low_priority:{k}" for d in docs for k in [filters.low_priority_key(d.title)] if k)
    target, rest = split_tob(docs, filters)
    if target:                                      return "tob_primary", None, flags     # rest は別 plan
    if any(filters.title_is_tob(d.title) and not _is_target(d.title, filters) for d in docs):
        return "normal", None, flags + ("tob_buyer",)
    return "normal", None, flags

# runner.py
def run_once(conn, now, cfg, filters, calendar, state_of):
    coverage = load_coverage(conn, now, cfg)
    rows = queries.events_after(conn, _low(coverage), limit=cfg.bundle.max_per_cycle * 20)
    plans = plan_bundles([_view(r) for r in rows], coverage, now, cfg, filters, calendar)
    staged = []                                          # (plan, StateResult | None, 追加 flags)
    for p in plans:                                      # トランザクションの外で state を組む（task 017）
        if p.bundle_role == "excluded":
            staged.append((p, None, ())); continue
        try:
            staged.append((p, state_of(p), ()))
        except JevfwdError as e:
            log.warning("state 構築に失敗。state 無しで bundle を残す: %s %s", p.event_ids, e)
            staged.append((p, None, (f"state_error:{type(e).__name__}",)))
    ids = []
    with db.transaction(conn):
        fresh = load_coverage(conn, now, cfg)            # BEGIN IMMEDIATE の下で読み直す
        for p, st, extra in staged:
            if any(i in fresh.covered for i in p.event_ids) and p.supersedes_id is None:
                log.info("既にカバー済みのため作らない: %s", p.event_ids); continue
            ids.append(repo.insert_bundle(conn, _to_row(p, st, extra, now, cfg)))
    return ids

def _to_row(p, st, extra, now, cfg):                     # NewBundle（01-凍結ログ 3.2）
    return NewBundle(code=p.code, anchor_published_at=p.anchor_published_at, session=p.session,
                     primary_event_id=p.primary_event_id, event_ids_json=canonical(list(p.event_ids)),
                     logical_docs_json=canonical([{"title": d.title, "event_ids": list(d.event_ids)} for d in p.logical_docs]),
                     bundle_role=p.bundle_role, skip_reason=p.skip_reason,
                     flags_json=canonical(list(p.flags) + list(st.flags if st else ()) + list(extra)),
                     state_json=st.state_json if st else None,            # 生のまま（05 ★6）
                     state_version=cfg.judge.state_version if st else None,
                     state_chars=st.state_chars if st else None,
                     state_completeness_json=canonical(st.completeness) if st else None,
                     supersedes_id=p.supersedes_id, created_at=to_utc_str(now))
```
