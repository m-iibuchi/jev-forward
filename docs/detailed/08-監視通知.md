## 1. 責務

- **生存監視**：常駐プロセスの beat（`heartbeat` 表）を集約し、途絶・滞留・ディスク・失敗率・時計のずれを ntfy に通知する（ADR 028）
- **通知**：ntfy への送信を1か所に閉じ込める。トピック名は秘密（`NTFY_TOPIC`）で、ログにも例外メッセージにも出さない
- **台帳**：凍結9テーブルの追記行を日次でハッシュ連鎖し `ledger` に残す（ADR 021）。NAS 側のコピーで全行を再計算して検証する
- **原本 PDF の保持期限**：NAS への転送が確認できた日付ディレクトリを `storage.raw_pdf_retention_days` 経過後に VPS から消す（ADR 018）
- **配備**：本番イメージ、supervisord、compose、日次バックアップ、VPS の初回手順

しないこと：TDnet・TypeSafe・J-Quants への接続（`fetch` `judge` `market`）、ダイジェスト通知の本文づくり（11-ダイジェスト模擬執行。通知の送信経路だけを `notify.py` が提供する）、日次コストの算出そのもの（07-判定が `judgments.input_chars` から求める。ここでは上限超過の**検知と通知**だけ。4.5）、週次の固定10件再判定（M8）。

M2（fetcher）と M4（judge_worker）が保留のままでも、bundler と heartbeat だけで段階1の稼働（監視・台帳・バックアップが 7 日間回る）を始められる構成にする。`monitor.watch` に無いプロセスは監視しない。

### 3.1 `monitor/notify.py`

```python
class Notifier(Protocol):
    def send(self, key: str, title: str, message: str, *, priority: int = 3,
             tags: Sequence[str] = ()) -> str: ...
        # 返り値は "sent" | "failed" | "suppressed"。例外は投げない

class NtfyNotifier:
    """POST {base_url}/{topic}。トピックはコンストラクタでだけ受け取り、属性名は _topic、repr に出さない"""
    def __init__(self, client: httpx.Client, base_url: str, topic: str,
                 cooldown_sec: int, now: Callable[[], datetime]) -> None: ...

class NullNotifier:
    """送らずに記録だけする（テスト、--dry-run）。sent: list[tuple[key, title, message]]"""
```

- `key` は抑制の単位（`missing:bundler` `stuck:bundler` `disk` `clock` `fail_rate:fetch` `fail_rate:judge` `cost` `backup_age` `recovered:bundler`）。同じ `key` は `cooldown_sec` の間 `"suppressed"`。抑制の状態はプロセス内メモリ（再起動でリセットされてよい。再起動直後に1回多く通知されるのは許容）
- 送信は `httpx.Client.post(url, content=message.encode("utf-8"), headers={"Title": title, "Priority": str(priority), "Tags": ",".join(tags)})`、timeout は `monitor.notify_timeout_sec`。2xx 以外と例外は `"failed"`（WARN ログ。URL・トピックはログに出さない。`SecretMaskFilter` にも掛かるが、そもそも文字列化しない）
- `Title` ヘッダは ASCII しか通らない実装があるので、`title` は `"jevfwd <key>"` の形に固定し、日本語は本文（`message`）に書く

```python
    watched: dict[str, dict]           # process -> {"age_sec": .., "ok": .., "status": "ok"|"missing"|"error"}

def collect(conn, now: datetime, cfg: Settings, probe: Probe, state: MonitorState) -> tuple[Summary, list[Alert]]:

def run_once(conn, now: datetime, cfg: Settings, probe: Probe, notifier: Notifier,
             state: MonitorState) -> int:
    """1周期。collect → 通知（復旧判定は state で）→ 自分の beat を1行。返り値は送った通知の数"""

class MonitorState:
    """プロセス内の状態：起動時刻（起動猶予の判定）、起動時の時計ずれ、直前の周期で missing だったプロセス集合（復旧通知用）"""

def check_clock(now: datetime, probe: Probe, cfg: Settings) -> float | None:
```

```python
GENESIS_HASH = "0" * 64

def normalize_row(values: Sequence[object]) -> str:
    """1行を ADR 021 の 3 の規則で JSON 配列の文字列にする"""

    """from_id < id <= to_id の行を id 昇順に normalize_row し '\\n' で連結して sha256。行が無ければ sha256(b'')"""

def chain_hash(prev_hash: str, schema_version: int, parts: Sequence[tuple[str, int, int, str]]) -> str:
    """ADR 021 の 5"""

def compute(conn, now: datetime) -> NewLedgerEntry:
    """前回行を読み、各表の to を採り、ハッシュを計算して NewLedgerEntry を返す。呼び出し側が transaction の中で呼ぶ"""

def append(conn, now: datetime) -> int | None:
    """db.transaction の中で compute → insert_ledger_entry。同日の行が既にあれば None（IntegrityError を捕まえて INFO）"""

@dataclass(frozen=True, slots=True)
class Mismatch:
    day: str
    table: str | None        # None なら chain_hash 自体の不一致
    expected: str
    actual: str

def verify(conn) -> list[Mismatch]:
    """ledger の全行を ledger_id 昇順に再計算し、detail_json の各表のハッシュと chain_hash を突き合わせる。空なら一致"""
```

`ledger` 表自身の範囲：当日の計算では「前回 ledger 行まで」（`to = MAX(ledger_id)` は当日 INSERT する行を含まない。INSERT 前に採るので自然にそうなる）。`verify` はこれを前提に、行 `k` の再計算で `ledger` の範囲が `[前回 to, 行 k-1 の ledger_id]` になることを確かめる。

## 4. データ契約

### 4.1 `heartbeat` 行の使い方（01-凍結ログ 4.3 の列はそのまま）

| `process` | 書く側 | 周期 | `ok=0` のとき `note` |
|---|---|---|---|
| `bundler` | `cli.cmd_bundle` | `bundle.poll_sec` | `bundler stuck: event_id=.. pending=..`（04-束ね 5章）、または例外のメッセージ |
| `fetcher` | M2 | `fetch.interval_sec` | 06 で決める |
| `judge_worker` | M4 | `judge.poll_sec` | 07 で決める |
| `heartbeat` | 本書 | `monitor.heartbeat_sec` | `note` は常に 4.2 の JSON（`ok=0` は警報が1つ以上あった周期） |
| `backup` | `prune-pdf` と `backup_to_nas.sh`（`ledger-append` 経由） | 日次 | `pruned dirs=N files=M` / `ledger day=.. chain_hash=..` |

`queue_depth` は bundler だけが書く（未カバー events の件数。04-束ね 5章）。他は NULL。

### 4.2 heartbeat プロセスの `note`（`Summary` の JSON）

```json
{"disk_pct": 41,
 "watched": {"bundler": {"age_sec": 12, "ok": 1, "status": "ok"},
             "heartbeat": {"age_sec": 60, "ok": 1, "status": "ok"}},
 "fetch_fail_rate": null, "judge_error_rate": null,
 "clock_skew_sec": 0.4, "last_backup_age_hours": 7.5,
 "alerts": []}
```

`canonical()` で保存する（キー順固定）。`status` は `ok` / `missing`（4.3）/ `error`（最新 beat が `ok=0`）。`fetch_fail_rate` `judge_error_rate` は対象行が `monitor.min_samples_for_rate` 未満なら null。

### 4.3 警報の規則（`collect`）

| key | 条件 | priority | 本文の要素 |
|---|---|---|---|
| `missing:<p>` | `monitor.watch` の `<p>` について、最新 beat の `ts` が `now - 周期 × monitor.missing_beats_alert` より古い、または行が1つも無い（起動から `周期 × missing_beats_alert` 経過後） | 5 | プロセス名、最後の beat の時刻（JST）、経過秒 |
| `recovered:<p>` | 前の周期で `missing` だった `<p>` の beat が戻った | 3 | プロセス名 |
| `stuck:<p>` | `<p>` の最新 beat が `ok=0` | 4 | `note` の先頭 200 字 |
| `disk` | `used/total*100 >= monitor.disk_alert_pct` | 4 | 使用率、`storage.db_path` のパス |
| `fail_rate:fetch` | 直近 `monitor.rate_window_sec` の `events` で `pdf_status='failed'` の割合 ≥ `monitor.fetch_fail_rate_alert`（分母 ≥ `min_samples_for_rate`） | 4 | 割合、件数 |
| `fail_rate:judge` | 同じ窓の `judgments` で `error_type IS NOT NULL` の割合 ≥ `monitor.judge_error_rate_alert` | 4 | 割合、件数、最多の `error_type` |
| `clock` | `abs(clock_skew_sec) > monitor.clock_skew_alert_sec`（起動時の1回だけ。参照時刻が取れなければ警報せず INFO） | 4 | ずれ秒 |
| `backup_age` | `process='backup'` の最新 beat が `monitor.backup_max_age_hours` より古い、または無い（起動から同時間経過後） | 4 | 経過時間 |
| `cost` | `monitor.daily_cost_limit_jpy` が設定されていて、当日（JST）の `judgments.input_chars` 合計 × `monitor.cost_per_1k_chars_jpy / 1000` が上限以上（task 004 の係数。null なら判定しない） | 5 | 概算額、件数。**新規判定の停止は 07-判定側**（同じ式で判定前に見る） |

同じ周期に複数の警報があっても、それぞれ別の `key` で送る（1通にまとめない。抑制が key 単位のため）。

### 4.4 参照時刻（時計のずれ）

VPS は NTP 同期が前提（基本設計 6章）。確認は「ntfy の base_url に `HEAD` を送り、応答の `Date` ヘッダ（RFC 7231、秒精度）と `now` の差を取る」。`email.utils.parsedate_to_datetime` で読む。ntfy に届かなければ None（警報しない。到達不能は別の問題として `missing` や通知失敗で分かる）。`Date` は秒精度なので 1 秒未満の差は意味を持たない。閾値 `monitor.clock_skew_alert_sec` の既定は 5。

### 4.5 日次コストの扱い

係数（task 004）が決まるまで `monitor.cost_per_1k_chars_jpy` は null、`daily_cost_limit_jpy` も null で、`cost` 警報は出ない。両方が入ったら、heartbeat が上限超過を通知し、07-判定は同じ式で判定前に上限を見て新規判定を止める（式は1か所 `monitor.heartbeat.daily_cost_jpy(conn, day, cfg)` に置き、07 がそれを呼ぶ。`judge` → `monitor` の import は境界表で禁止なので、**式は `store/queries.py` の集計（`sum_input_chars(conn, day_from_utc, day_to_utc)`）と `settings` の係数だけで書けるようにし、`judge` は同じ2つを使う**）。

### 4.6 台帳（ADR 021 をそのまま。実装の確認用に再掲）

- 対象と順序：`events, bundles, judgments, answers, heartbeat, ledger, question_versions, state_versions, my_calls`（`db.FROZEN_TABLES`）
- 範囲：`from` = 前回行の `detail_json.tables[t].to`（初回 0）、`to` = `MAX(<t>_id)`（行が無ければ `from`）。対象は `from < id <= to`
- 正規化：`PRAGMA table_info(t)` の列順に値を配列にし `json.dumps(ensure_ascii=False, separators=(",", ":"))`。`str` はそのまま、`int` はそのまま、`float` は `repr(x)` の**文字列**、`None` は `null`、`bytes` は `"hex:" + hex()`。`bool` は SQLite には無い（`int` になる）
- テーブルハッシュ：行を id 昇順に `\n` で連結し UTF-8 で `sha256`。行が無ければ `sha256(b"")` = `e3b0c442…b855`
- 連鎖：`sha256((prev + "\n" + str(schema_version) + "\n" + "\n".join(f"{t}:{from}:{to}:{hash}" for t in 順)).encode())`
- 行：`ledger(day=JST 暦日, rows_added=対象行数の合計, prev_hash, chain_hash, schema_version, detail_json=canonical({"tables": {t: {"from", "to", "hash"}}}), computed_at=UTC)`
- 原子性：`to` の採取・ハッシュ・INSERT を1つの `db.transaction`（`BEGIN IMMEDIATE`）で
- `verify`：行 `k`（`ledger_id` 昇順）について、`detail_json` の `from`/`to` で各表を再計算して `hash` と比べ、`prev_hash` が行 `k-1` の `chain_hash`（初回は GENESIS）であることと、`chain_hash` の再計算一致を見る。`from` が前行の `to` と一致することも見る（範囲の連続性）
- `REAL` の `repr` は Python の実装に依存するが、3.11 以降は最短表現で安定。`schema_version` を連鎖に含めるので、列追加の前後で規則が変わっても行ごとに判別できる

- 終了コード 3（スキーマ不一致）は `exitcodes` に入れて「期待された終了」にし、`autorestart=unexpected` で再起動ループに入れない（03-CLI 3.2）。`init-db` が先に走るので通常は起きない
- `init-db` はワーカーより `priority` が小さいので先に起動するが、supervisord は完了を待たない。ワーカーは `db.connect` で版を検査し、`init-db` より先に動いて exit 3 になっても再起動されないので、`startsecs=5` の間に `init-db` が終わる前提で、`bundler` `heartbeat` の `command` は `sh -c 'sleep 3 && jevfwd bundle'` ではなく **`jevfwd` 側で `db.connect` を `monitor.connect_retry_sec`（既定 30）秒まで再試行する**（`cli._connect_with_retry`。★4）。テストは T08-27
- 未実装のプロセスは `autostart=false` で登録だけしておく（`supervisorctl start fetcher` で手動起動も可）

### 4.11 `deploy/backup_to_nas.sh`（ホストの cron、毎日 02:00 JST = 17:00 UTC）

```bash
#!/usr/bin/env bash
# VPS の凍結ログと原本 PDF を NAS へ。順序：台帳 → スナップショット → rsync → 転送確認 → 保持期限の削除
set -euo pipefail
cd "$(dirname "$0")/.."                       # リポジトリのルート
COMPOSE="docker compose -f deploy/docker-compose.yml"
DB=data/db/jevfwd.sqlite                       # settings.yaml の storage.db_path と一致（T08-29 が検査）
PDF=data/raw/pdf                               # storage.raw_pdf_dir
CONFIRMED=data/backup/confirmed_days.txt       # storage.backup_confirmed_file
SNAP=data/backup/snapshots
NAS="${JEVFWD_NAS_TARGET:?NAS の rsync 先（user@host:/volume1/jevfwd）}"
KEEP=7
day=$(TZ=Asia/Tokyo date +%F)

$COMPOSE exec -T app jevfwd ledger-append                       # 1. 台帳（同日2回目は no-op）
mkdir -p "$SNAP" "$(dirname "$CONFIRMED")"
sqlite3 "$DB" ".backup '$SNAP/jevfwd-$day.sqlite'"             # 2. 一貫スナップショット
rsync -a --delete-after --partial "$SNAP/" "$NAS/snapshots/"   # 3. スナップショット
rsync -a --partial "$PDF/" "$NAS/pdf/"                          #    原本 PDF（削除は同期しない）
for d in "$PDF"/*/; do                                          # 4. 転送確認：件数とサイズを NAS 側と照合
  d=$(basename "$d")
  local_n=$(find "$PDF/$d" -type f | wc -l); local_b=$(du -sb "$PDF/$d" | cut -f1)
  remote=$(ssh "${NAS%%:*}" "find '${NAS#*:}/pdf/$d' -type f | wc -l; du -sb '${NAS#*:}/pdf/$d' | cut -f1")
  if [ "$remote" = "$local_n"$'\n'"$local_b" ]; then grep -qx "$d" "$CONFIRMED" 2>/dev/null || echo "$d" >> "$CONFIRMED"; fi
done
ls -1t "$SNAP"/jevfwd-*.sqlite | tail -n +$((KEEP + 1)) | xargs -r rm --   # 5. VPS 側のスナップショットは 7 日
$COMPOSE exec -T app jevfwd prune-pdf                            # 6. 転送確認済み・期限切れの PDF を削除
```

- NAS 側の検証は NAS で `jevfwd ledger-verify --db snapshots/jevfwd-<day>.sqlite`（NAS に Python 3.11 と本パッケージを入れるか、ローカル PC にコピーして実行）。`docs/配備手順.md` に手順
- rsync は VPS → NAS の push（NAS 側に SSH 鍵を置く）。NAS → VPS の pull にする場合はスクリプトを NAS 側に置き、`ledger-append` だけを VPS の cron に残す
- `JEVFWD_NAS_TARGET` は秘密ではない（ホスト名とパス）が、リポジトリには書かず cron の環境で渡す

### 4.12 `docs/配備手順.md` の骨子（M5 のセッションで書く）

1. VPS：Ubuntu LTS、Docker と Compose、`git clone`、`.env` を置く（3つの鍵。`NTFY_TOPIC` は推測されない長さ）

## 5. エラー時の振る舞い

| 事象 | 振る舞い |
|---|---|
| ntfy が 2xx 以外・接続失敗・タイムアウト | `send` は `"failed"` を返す（例外にしない）。WARN ログ（URL・トピックは出さない）。自分の beat の `note.alerts` に `<key>:failed` |
| `heartbeat` の周期で DB がロック待ち超過（`OperationalError`） | その周期は WARN ログだけで次周期へ。beat は書けないので、連続すれば他プロセスから見て途絶になる（それが正しい） |
| `monitor.watch` に `PERIOD_KEYS` に無い名前 | 起動時に `ConfigError`（黙って無視しない） |
| `ledger-append` で同日の行が既にある | `IntegrityError`（UNIQUE）を捕まえて INFO、exit 0、stdout `ledger day=<day> already` |
| `ledger-verify` で不一致 | stderr に不一致ごとに `day table expected actual`、exit 1。一致は stdout `verified entries=<n>` exit 0 |
| `ledger-verify` の対象 DB が版違い・トリガー欠落 | `db.connect` が `SchemaMismatchError` / `StoreError`。exit 3 / 1（改ざんの疑いとして扱い、検証はしない） |
| `prune-pdf` で `confirmed_days` ファイルが無い | 何も消さない。INFO |
| `prune-pdf` の削除でエラー（権限） | そのディレクトリを飛ばして続行。`heartbeat(process='backup', ok=0, note=...)` |
| 参照時刻が取れない | INFO、警報なし、`clock_skew_sec: null` |
| ワーカー起動時に `db.connect` が `SchemaMismatchError` | `monitor.connect_retry_sec` 秒まで 5 秒間隔で再試行（`init-db` の完了待ち）。超えたら exit 3（supervisord は再起動しない。人が見る） |

```python
# heartbeat.py
def collect(conn, now, cfg, probe, state):
    alerts, watched = [], {}
    for name in cfg.monitor.watch:
        key = PERIOD_KEYS.get(name) or _raise(ConfigError(f"monitor.watch に未知のプロセス: {name}"))
        period = _lookup(cfg, key)                       # "bundle.poll_sec" → cfg.bundle.poll_sec
        last = queries.recent_heartbeat(conn, name, limit=1)
        limit = period * cfg.monitor.missing_beats_alert
        if not last:
            age = None; status = "missing" if (now - state.started_at).total_seconds() > limit else "starting"
        else:
            age = (now - parse_utc(last[0]["ts"])).total_seconds()
            status = "missing" if age > limit else ("error" if last[0]["ok"] == 0 else "ok")
        watched[name] = {"age_sec": age, "ok": last[0]["ok"] if last else None, "status": status}
        if status == "missing": alerts.append(Alert(f"missing:{name}", f"{name} の生存ログが {age or '—'} 秒途絶（周期 {period}s × {cfg.monitor.missing_beats_alert}）", 5))
        if status == "error":   alerts.append(Alert(f"stuck:{name}", f"{name}: {last[0]['note'][:200]}", 4))
    used, total = probe.disk_usage(str(Path(cfg.storage.db_path).parent))
    pct = int(used * 100 / total) if total else None
    if pct is not None and pct >= cfg.monitor.disk_alert_pct: alerts.append(Alert("disk", f"ディスク使用率 {pct}%（{cfg.storage.db_path}）", 4))
    since = to_utc_str(now - timedelta(seconds=cfg.monitor.rate_window_sec))
    ff = queries.failure_rate(conn, "events", "pdf_status = 'failed'", "received_at", since)          # (failed, total)
    je = queries.failure_rate(conn, "judgments", "error_type IS NOT NULL", "requested_at", since)
    fetch_rate = _rate(ff, cfg); judge_rate = _rate(je, cfg)
    if fetch_rate is not None and fetch_rate >= cfg.monitor.fetch_fail_rate_alert: alerts.append(Alert("fail_rate:fetch", ..., 4))
    if judge_rate is not None and judge_rate >= cfg.monitor.judge_error_rate_alert: alerts.append(Alert("fail_rate:judge", ..., 4))
    backup = queries.recent_heartbeat(conn, "backup", limit=1)
    backup_age_h = (now - parse_utc(backup[0]["ts"])).total_seconds() / 3600 if backup else None
    if (backup_age_h is None and (now - state.started_at).total_seconds() > cfg.monitor.backup_max_age_hours * 3600) or (backup_age_h or 0) > cfg.monitor.backup_max_age_hours:
        alerts.append(Alert("backup_age", ..., 4))
    if cfg.monitor.daily_cost_limit_jpy is not None and cfg.monitor.cost_per_1k_chars_jpy is not None:
        chars = queries.sum_input_chars(conn, *_jst_day_bounds_utc(now))
        cost = chars * cfg.monitor.cost_per_1k_chars_jpy / 1000
        if cost >= cfg.monitor.daily_cost_limit_jpy: alerts.append(Alert("cost", f"本日の判定コスト概算 {cost:.0f} 円 ≥ 上限", 5))
    return Summary(pct, watched, fetch_rate, judge_rate, state.clock_skew, backup_age_h, []), alerts

def run_once(conn, now, cfg, probe, notifier, state):
    summary, alerts = collect(conn, now, cfg, probe, state)
    sent = 0; keys = []
    for a in alerts:
        r = notifier.send(a.key, f"jevfwd {a.key}", a.message, priority=a.priority); keys.append(f"{a.key}:{r}"); sent += r == "sent"
    missing_now = {a.key.split(":", 1)[1] for a in alerts if a.key.startswith("missing:")}
    for name in state.missing_before - missing_now:
        r = notifier.send(f"recovered:{name}", f"jevfwd recovered:{name}", f"{name} の生存ログが復旧", priority=3); keys.append(...)
    state.missing_before = missing_now
    with db.transaction(conn):
        repo.insert_heartbeat(conn, NewHeartbeat(ts=to_utc_str(now), process=PROCESS, ok=0 if alerts else 1,
                                                 note=canonical(asdict(replace(summary, alerts=keys)))))
    return sent

# ledger.py
def normalize_row(values):
    out = []
    for v in values:
        if isinstance(v, bytes): out.append("hex:" + v.hex())
        elif isinstance(v, float): out.append(repr(v))
        else: out.append(v)                              # str / int / None
    return json.dumps(out, ensure_ascii=False, separators=(",", ":"))

def table_hash(conn, table, from_id, to_id):
    h = hashlib.sha256(); first = True
    for row in queries.rows_in_id_range(conn, table, from_id, to_id):      # id 昇順、PRAGMA table_info の列順
        if not first: h.update(b"\n")
        h.update(normalize_row(tuple(row)).encode("utf-8")); first = False
    return h.hexdigest()

def compute(conn, now):
    prev = queries.last_ledger(conn)
    prev_hash = prev["chain_hash"] if prev else GENESIS_HASH
    prev_to = json.loads(prev["detail_json"])["tables"] if prev else {}
    parts, tables, rows_added = [], {}, 0
    for t in FROZEN_ORDER:
        frm = int(prev_to.get(t, {}).get("to", 0)); to = max(queries.max_id(conn, t), frm)
        h = table_hash(conn, t, frm, to)
        parts.append((t, frm, to, h)); tables[t] = {"from": frm, "to": to, "hash": h}; rows_added += to - frm
    sv = queries.current_schema_version(conn)
    return NewLedgerEntry(day=jst_day(now), rows_added=rows_added, prev_hash=prev_hash,
                          chain_hash=chain_hash(prev_hash, sv, parts), schema_version=sv,
                          detail_json=canonical({"tables": tables}), computed_at=to_utc_str(now))

def append(conn, now):
    try:
        with db.transaction(conn):
            return repo.insert_ledger_entry(conn, compute(conn, now))
    except db.IntegrityError as e:
        if "ledger.day" in str(e) or "UNIQUE" in str(e): log.info("本日の台帳行は既にある: %s", jst_day(now)); return None
        raise

def verify(conn):
    out, prev_hash, prev_to = [], GENESIS_HASH, {}
    for row in queries.ledger_entries(conn):
        detail = json.loads(row["detail_json"])["tables"]; parts = []
        if row["prev_hash"] != prev_hash: out.append(Mismatch(row["day"], None, prev_hash, row["prev_hash"]))
        for t in FROZEN_ORDER:
            frm, to, expected = detail[t]["from"], detail[t]["to"], detail[t]["hash"]
            if frm != prev_to.get(t, 0): out.append(Mismatch(row["day"], t, f"from={prev_to.get(t, 0)}", f"from={frm}"))
            actual = table_hash(conn, t, frm, to)
            if actual != expected: out.append(Mismatch(row["day"], t, expected, actual))
            parts.append((t, frm, to, expected))
        recomputed = chain_hash(row["prev_hash"], row["schema_version"], parts)
        if recomputed != row["chain_hash"]: out.append(Mismatch(row["day"], None, recomputed, row["chain_hash"]))
        prev_hash = row["chain_hash"]; prev_to = {t: detail[t]["to"] for t in FROZEN_ORDER}
    return out
```
