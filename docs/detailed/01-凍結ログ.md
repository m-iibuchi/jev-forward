# 01: 凍結ログ（`src/jevfwd/store/`）

- 対象：`store/schema.sql` `store/db.py` `store/rows.py` `store/repo.py` `store/queries.py` `store/freeze.py` `store/migrations/`
- マイルストーン：M1
- 関連：CLAUDE.md ルール1・6、要件 F4-1〜F4-4、基本設計 3.5・4章、ADR 004・009・011・014・015・016・019・020・021・022・024、task 013
- 版：2026-09-20 初版（同日 M3 追補：3.4 に M3 の読み取り関数、T01-14 の実測値、4.5 に ADR 024。同日 M1 実装で 7章 `_OPS` の解決方法を確定。task 018）

## 1. 責務

- SQLite ファイル1つに、凍結ログ（追記専用9テーブル）・採点キャッシュ（4テーブル）・`schema_version` を持つ
- **書き込みは INSERT のみ**。UPDATE / DELETE はアプリ層（`repo.py` に関数が無い）と DB 層（トリガー）の両方で拒否する（ADR 014）
- 接続の PRAGMA、前進のみのマイグレーション、トランザクション境界を `db.py` に閉じ込める
- 読み取りは `queries.py`。他モジュールは `sqlite3` を直接触らず、`repo` / `queries` / `db.transaction` だけを使う

しないこと：業務判断（束ね、除外、遅延判定）。列に何を入れるかを決めるのは各モジュール。`store` は形だけを守る。

## 2. 依存

- 標準ライブラリのみ（`sqlite3` `dataclasses` `contextlib` `pathlib` `json`）
- `jevfwd.common`（`timeutil` `hashing` `jsonutil` `errors`）
- 他の業務モジュールを import しない（`store` は全員から使われる側）

SQLite は 3.31 以上（ローカル WSL が 3.31.1、Docker `python:3.11-slim`（bookworm）は 3.40）。`RETURNING`（3.35）・`STRICT`（3.37）・`->>`（3.38）は使わない。`cursor.lastrowid` で ID を得る。

## 3. 公開インターフェース

### 3.1 `store/db.py`

```python
CURRENT_SCHEMA_VERSION: int = 1
FROZEN_TABLES: tuple[str, ...] = (
    "events", "bundles", "judgments", "answers", "heartbeat",
    "ledger", "question_versions", "state_versions", "my_calls",
)
EXPECTED_TRIGGER_COUNT: int = len(FROZEN_TABLES) * 2   # 18

# store 以外のモジュールは sqlite3 を import しない（00-共通規約 T00-15）。例外はこの別名で捕まえる
IntegrityError = sqlite3.IntegrityError
OperationalError = sqlite3.OperationalError

def connect(path: str | Path) -> sqlite3.Connection:
    """接続して PRAGMA を設定し、スキーマ版とトリガー本数を検査する。
    - isolation_level=None（sqlite3 モジュールの自動 BEGIN を使わない。書き込みは transaction() を通す）
    - PRAGMA journal_mode=WAL, foreign_keys=ON, recursive_triggers=ON, synchronous=FULL, busy_timeout=5000
      （PRAGMA はトランザクション外で発行する。foreign_keys はトランザクション内では無視される）
    - row_factory=sqlite3.Row
    - schema_version が無い / CURRENT_SCHEMA_VERSION と異なる → SchemaMismatchError（終了コード3、"jevfwd init-db を実行"）
    - trg_* トリガーが EXPECTED_TRIGGER_COUNT 本でない → StoreError（ADR 014「外さない」の検知）
    自動マイグレーションはしない。"""

@contextmanager
def transaction(conn: sqlite3.Connection) -> Iterator[sqlite3.Connection]:
    """BEGIN IMMEDIATE … COMMIT / 例外時 ROLLBACK。
    WAL で「SELECT してから INSERT」の遅延 BEGIN は、他プロセスのコミット後に SQLITE_BUSY_SNAPSHOT で即失敗し
    busy_timeout が効かない。書き込みを含む処理は必ずこの中で行う。入れ子は不可（ProgrammingError）。"""

def migrate(path: str | Path) -> int:
    """schema_version を現在の版まで前進させ、適用後の版を返す。冪等。
    - ファイルが無ければ作る（親ディレクトリも）。PRAGMA は connect と同じ
    - BEGIN IMMEDIATE を取ってから版を再読する（supervisord が全プロセスを同時に起動しても二重適用しない）
    - 版0（空）なら store/schema.sql、以降は store/migrations/NNN_*.sql を番号順に適用。各ファイルは
      自身の中で BEGIN IMMEDIATE … INSERT INTO schema_version … COMMIT を持つ（executescript は先に暗黙 COMMIT するため）
    - DB の版が CURRENT_SCHEMA_VERSION より大きい → SchemaMismatchError（古いコードで新しい DB を開かない）
    - 既存行を書き換えるマイグレーションは禁止（ADR 014）。列追加は ALTER TABLE ADD COLUMN（トリガーと衝突しない）"""
```

### 3.3 `store/repo.py`（INSERT のみ）

```python
__all__ = [
    "insert_event", "insert_bundle", "insert_judgment", "insert_answer", "insert_answers",
    "insert_heartbeat", "insert_ledger_entry", "insert_question_version", "insert_state_version",
    "insert_my_call",

def insert_heartbeat(conn, row: NewHeartbeat) -> int: ...
def insert_ledger_entry(conn, row: NewLedgerEntry) -> int: ...

def insert_state_version(conn, row: NewStateVersion) -> int: ...
def insert_my_call(conn, row: NewMyCall) -> int: ...
```

規約：

- `INSERT INTO <table> (<cols>) VALUES (?, …)` のみ。`INSERT OR REPLACE` `INSERT OR IGNORE` `ON CONFLICT` は使わない（REPLACE は暗黙 DELETE、ON CONFLICT DO UPDATE は UPDATE。どちらもトリガーで落ちるが、書かないことを規約とテストで担保）
- `BEGIN` も `COMMIT` もしない。呼び出し側が `with db.transaction(conn):` で囲む
- 制約違反（`sqlite3.IntegrityError`）はそのまま伝播させる（握りつぶさない。CHECK / UNIQUE / FK / append-only の区別はメッセージで分かる）
- 公開名に `update` `delete` `upsert` `replace` `remove` `set_` `modify` を含む名前を置かない。ソースに `UPDATE` `DELETE` `REPLACE` `ON CONFLICT` の SQL トークンを書かない（テスト T01-11）

### 3.5 `store/freeze.py`（版の凍結。CLI `freeze-questions` / `freeze-state` が使う）

```python
def freeze_version(conn, *, table: Literal["question_versions", "state_versions"], version: str,
                   text: str, sha256: str, now: str) -> tuple[str, str, str]:
    """版ファイルの本文を凍結する（ADR 020）。返り値は (status, sha256, frozen_at)。status は "frozen" | "already"。
    - transaction 内で既存行を読む。無ければ INSERT（json/spec 列に text をそのまま）
    - あって sha256 一致 → ("already", sha256, 既存 frozen_at)。INSERT しない
    - あって不一致 → ConfigError（メッセージに両方の sha256 と「版ファイルを変更してはいけない」）
    - INSERT が IntegrityError（UNIQUE。並行実行で先に入れられた）なら ROLLBACK 後に1回だけやり直す"""
```

## 4. データ契約

### 4.1 時刻・日付・コード（00-共通規約 3章の要約）

- `*_at` `ts` 列：UTC `YYYY-MM-DDTHH:MM:SS+00:00`。DDL の GLOB CHECK で強制。`Z` や naive は拒否される
- `day` `date` `as_of` `listed_on` `entry_date` `exit_date`：JST 暦日 `YYYY-MM-DD`
- `code`：TDnet の5文字（`35600` `590A0` `13264`）。`length(code) = 5` を CHECK。Jev に渡す4文字表示は `common.codes.display_code`
- JSON 列：`*_json` は正規 JSON（`common.jsonutil.canonical`）。ただし `request_json` `response_json` `question_versions.json` `state_versions.spec` は受け取った文字列をそのまま

### 4.2 基本設計4章からの変更点（★）

| ★ | 変更 | 理由 |
|---|---|---|
| 1 | 凍結9テーブルすべてに明示の `<table>_id INTEGER PRIMARY KEY`。`answers` `ledger` `question_versions` `state_versions` `my_calls` の自然キーは `UNIQUE` に降格 | 複合PK / TEXT PK のテーブルは rowid が `VACUUM` で振り直され、ledger の id 範囲（ADR 021）が壊れる |
| 2 | `heartbeat` は `(ts, process)` を UNIQUE にせず INDEX のみ | 同一秒に同じプロセスが2行書く（再起動連発）のは事実として残す。task 007 の「heartbeat PK 修正」は surrogate PK + index で満たす |
| 3 | `bundles.supersedes_id INTEGER REFERENCES bundles(bundle_id)` | 猶予後に届いた event の束ね直し・誤束ねの訂正（ADR 014 Consequences）。events は1PDF=1行で訂正は新PDF、judgments は `purpose` で表せるので持たない |
| 4 | `judgments.question_version` → `question_versions(version)`、`judgments.state_version` `bundles.state_version` → `state_versions(version)` の外部キー | 「凍結済みの版しか使えない」（ADR 020、F3-6）を DB 層でも担保 |
| 5 | `ledger` に `prev_hash` `schema_version` `detail_json` `computed_at` | ハッシュ連鎖の再計算に必要（ADR 021） |
| 6 | 列挙列・0/1 フラグ・時刻書式・コード長・SHA-256 長に CHECK。`bundles` に `(bundle_role='excluded') = (skip_reason IS NOT NULL)` | 不正値が凍結されると後から直せない |
| 7 | `events.source` に `fixture` を追加 | 週次再判定の固定10件は `source='fixture'` の合成 event 行を作り、`primary_event_id NOT NULL` の FK を満たす（ADR 015。2026-09-20 決定） |
| 8 | インデックス追加 | 3.2 の候補検索、ダイジェストの期間検索、heartbeat の直近3行 |

### 4.3 `src/jevfwd/store/schema.sql`（全文）

実装セッションはこのブロックをそのまま `src/jevfwd/store/schema.sql` に置く。検証済み（SQLite 3.31.1、2026-09-20）：トリガー18本、`INSERT OR REPLACE` と `ON CONFLICT DO UPDATE` も `append-only:` で失敗、未凍結 `question_version` は FK で失敗、4文字コード・`Z` 終端時刻・不明列挙値は CHECK で失敗、`ALTER TABLE ADD COLUMN` は通る。

```sql
-- src/jevfwd/store/schema.sql — 凍結ログ DDL（版1）
-- 正本は docs/detailed/01-凍結ログ.md。変更は store/migrations/NNN_*.sql で前進のみ。
-- 時刻列（*_at, ts）は UTC 'YYYY-MM-DDTHH:MM:SS+00:00'、日付列（day, date, as_of, listed_on）は JST 暦日 'YYYY-MM-DD'。
-- PRAGMA（WAL, foreign_keys, recursive_triggers 等）は db.connect() が接続ごとに設定する。ここには書かない。

BEGIN IMMEDIATE;

CREATE TABLE schema_version (
  version    INTEGER PRIMARY KEY,
  applied_at TEXT NOT NULL CHECK (applied_at GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]T[0-9][0-9]:[0-9][0-9]:[0-9][0-9]+00:00')
);

-- ---------------------------------------------------------------
-- 凍結テーブル（追記専用。末尾のトリガーで UPDATE / DELETE を拒否）
-- ---------------------------------------------------------------

CREATE TABLE events (
  event_id      INTEGER PRIMARY KEY,
  code          TEXT NOT NULL CHECK (length(code) = 5),            -- TDnet 5文字（35600, 590A0, 13264）
  company       TEXT,
  title         TEXT NOT NULL,
  published_at  TEXT NOT NULL CHECK (published_at GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]T[0-9][0-9]:[0-9][0-9]:[0-9][0-9]+00:00'),
  received_at   TEXT NOT NULL CHECK (received_at  GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]T[0-9][0-9]:[0-9][0-9]:[0-9][0-9]+00:00'),
  fetch_lag_sec INTEGER,                                             -- received_at - published_at（ADR 009）
  pdf_url       TEXT,
  pdf_path      TEXT,
  pdf_sha256    TEXT UNIQUE CHECK (pdf_sha256 IS NULL OR (length(pdf_sha256) = 64 AND pdf_sha256 NOT GLOB '*[^0-9a-f]*')),
  pdf_status    TEXT NOT NULL CHECK (pdf_status IN ('ok', 'failed', 'none')),
  body_text     TEXT,
  body_chars    INTEGER,
  scan_suspect  INTEGER CHECK (scan_suspect IN (0, 1)),
  xbrl_json     TEXT,
  source        TEXT NOT NULL DEFAULT 'tdnet' CHECK (source IN ('tdnet', 'fixture'))  -- fixture: 週次再判定用の合成行（ADR 015）
);
CREATE INDEX idx_events_code_published ON events (code, published_at);
CREATE INDEX idx_events_published      ON events (published_at);

CREATE TABLE bundles (
  bundle_id               INTEGER PRIMARY KEY,
  code                    TEXT NOT NULL CHECK (length(code) = 5),
  anchor_published_at     TEXT NOT NULL CHECK (anchor_published_at GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]T[0-9][0-9]:[0-9][0-9]:[0-9][0-9]+00:00'),
  session                 TEXT NOT NULL CHECK (session IN ('after_close', 'pre_open', 'intraday')),   -- ADR 011
  primary_event_id        INTEGER NOT NULL REFERENCES events (event_id),
  event_ids_json          TEXT NOT NULL,                              -- 束ねた全 event_id の配列
  logical_docs_json       TEXT NOT NULL,                              -- [{title, event_ids}]（ADR 016）
  bundle_role             TEXT NOT NULL CHECK (bundle_role IN ('normal', 'tob_primary', 'tob_attached', 'excluded', 'fixture')),
  skip_reason             TEXT CHECK (skip_reason IS NULL OR skip_reason IN ('excluded_instrument', 'excluded_supervised', 'excluded_new_listing', 'excluded_title')),
  flags_json              TEXT NOT NULL DEFAULT '[]',                 -- low_priority:*, truncated, provisional_only, scan_suspect（ADR 019）
  state_json              TEXT,
  state_version           TEXT REFERENCES state_versions (version),
  state_chars             INTEGER,
  state_completeness_json TEXT,
  supersedes_id           INTEGER REFERENCES bundles (bundle_id),     -- 訂正時に旧 bundle を指す（ADR 014）
  created_at              TEXT NOT NULL CHECK (created_at GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]T[0-9][0-9]:[0-9][0-9]:[0-9][0-9]+00:00'),
  CHECK ((bundle_role = 'excluded') = (skip_reason IS NOT NULL))
);
CREATE INDEX idx_bundles_code_anchor ON bundles (code, anchor_published_at);
CREATE INDEX idx_bundles_supersedes  ON bundles (supersedes_id);

CREATE TABLE judgments (
  judgment_id      INTEGER PRIMARY KEY,
```

### 4.4 マイグレーションの規約

- `store/migrations/NNN_<snake_name>.sql`（`002_add_events_xbrl_url.sql` 等）。`NNN` は `schema_version.version` と一致
- 各ファイルは `BEGIN IMMEDIATE;` で始まり `INSERT INTO schema_version (version, applied_at) VALUES (NNN, strftime('%Y-%m-%dT%H:%M:%S+00:00','now'));` `COMMIT;` で終わる
- 許可：`CREATE TABLE` `CREATE INDEX` `CREATE TRIGGER` `ALTER TABLE … ADD COLUMN`（NOT NULL には定数 DEFAULT が必要。CHECK / UNIQUE / PK は ADD COLUMN で足せない）
- 禁止：`UPDATE` `DELETE` `DROP TRIGGER`（凍結テーブル）、既存行の値を変える操作すべて
- テーブル再構築（列の削除・型変更）が避けられないとき：ADR を書いてから、(1) `PRAGMA foreign_keys=OFF` をトランザクション外で、(2) 新表 `CREATE`、(3) `INSERT INTO new SELECT … FROM old`、(4) 行数と ADR 021 のテーブルハッシュが一致することを確認、(5) 旧表 `DROP`（凍結テーブルの DROP は該当トリガーを先に `DROP TRIGGER`）、(6) `RENAME`、(7) トリガー再作成、(8) `PRAGMA foreign_key_check`、(9) `foreign_keys=ON`。ledger の `detail_json.from/to` は id を保つので再構築後も連鎖は続く

### 4.5 訂正の作法

- 凍結テーブルの行は直さない。`bundles` の訂正は新しい行を `supersedes_id=<旧 bundle_id>` で追加する。「現在の bundle」＝ `NOT EXISTS (SELECT 1 FROM bundles b2 WHERE b2.supersedes_id = b.bundle_id)`。主分析・ダイジェスト・採点は現在の bundle のみを対象にする（基本設計 3.8 の母集団条件に加える）
- `events` の誤り（表題の文字化け等）は新しい PDF 取得＝新しい行。`pdf_sha256` が同じなら再登録できないので、その場合は `bundles.flags_json` に `event_note:<内容>` を付けて bundle 側で注記する
- `judgments` の再実行は `purpose` で区別する（ADR 015）。同じ bundle への `full` の2回目は許容されるが、主分析は `judgment_id` 最小の `full` 1件を使う（採点 10-採点.md で規定）
- 表題のみで暫定判定した bundle に後から PDF が届いた場合は、**同じ bundle を使い回さず** superseding bundle を作る（ADR 024。`events` が追記専用なので後から届く本文は新しい event 行になる）。本判定の state は新しい bundle の `state_json` にある

## 5. エラー時の振る舞い

| 事象 | 振る舞い |
|---|---|
| DB ファイル無し / `schema_version` 無し / 版が古い・新しい | `connect` が `SchemaMismatchError`（`StoreError` の派生）。CLI は終了コード3。メッセージに現在版・期待版・「`jevfwd init-db` を実行」を含む |
| トリガー本数が18でない | `connect` が `StoreError`。プロセスは起動しない |
| CHECK / UNIQUE / FK / append-only 違反 | `sqlite3.IntegrityError` をそのまま伝播。`repo` は捕まえない。呼び出し側（各ワーカー）が捕まえて heartbeat に書く |
| ロック待ち超過（`busy_timeout` 5秒） | `sqlite3.OperationalError: database is locked`。黙って捨てない。ワーカーは次周期に再試行 |
| `transaction` の入れ子 | `sqlite3.ProgrammingError`（実装の誤り。テストで検出） |
| `count_rows` に未知のテーブル名 | `ValueError`（SQL インジェクション防止のため識別子は許可リスト） |
| マイグレーションファイルの欠番・重複番号 | `migrate` が `StoreError`。何も適用しない |

## 6. 設定項目

- `storage.db_path`（既定 `data/db/jevfwd.sqlite`）：`connect` / `migrate` に渡すパス。CLI が `Settings` から読んで渡す。`store` 自身は設定を読まない
- PRAGMA の値（WAL、`busy_timeout` 5000、`synchronous=FULL`）はコード定数。変える判断は ADR

## 7. 擬似コード

```python
# db.py
_PRAGMAS = (("journal_mode", "WAL"), ("foreign_keys", "ON"), ("recursive_triggers", "ON"),
            ("synchronous", "FULL"), ("busy_timeout", "5000"))

def _open(path):
    conn = sqlite3.connect(str(path), isolation_level=None, timeout=5.0)
    conn.row_factory = sqlite3.Row
    for k, v in _PRAGMAS:
        conn.execute(f"PRAGMA {k}={v}")
    return conn

def connect(path):
    if not Path(path).exists():
        raise SchemaMismatchError(f"DB がありません: {path}。jevfwd init-db を実行")
    conn = _open(path)
    v = queries.current_schema_version(conn)
    if v != CURRENT_SCHEMA_VERSION:
        conn.close()
        raise SchemaMismatchError(f"schema_version={v}, 期待={CURRENT_SCHEMA_VERSION}。jevfwd init-db を実行")
    n = conn.execute("SELECT count(*) FROM sqlite_master WHERE type='trigger' AND name GLOB 'trg_*'").fetchone()[0]
    if n != EXPECTED_TRIGGER_COUNT:
        conn.close()
        raise StoreError(f"追記専用トリガーが {n} 本（期待 {EXPECTED_TRIGGER_COUNT}）。DB が改変されています")
    return conn

@contextmanager
def transaction(conn):
    if conn.in_transaction:
        raise sqlite3.ProgrammingError("transaction() の入れ子は不可")
    conn.execute("BEGIN IMMEDIATE")
    try:
        yield conn
    except BaseException:
        conn.execute("ROLLBACK")
        raise
    else:
        conn.execute("COMMIT")

def migrate(path):
    Path(path).parent.mkdir(parents=True, exist_ok=True)
    conn = _open(path)
    try:
        scripts = _load_scripts()                      # {1: schema.sql, 2: migrations/002_*.sql, ...} 欠番・重複は StoreError
        while True:
            conn.execute("BEGIN IMMEDIATE")            # 版の読み取りと適用判断をロック下で行う
            v = queries.current_schema_version(conn)
            conn.execute("COMMIT")
            if v > CURRENT_SCHEMA_VERSION:
                raise SchemaMismatchError(f"DB の版 {v} がコードの版 {CURRENT_SCHEMA_VERSION} より新しい")
            if v == CURRENT_SCHEMA_VERSION:
                return v
            conn.executescript(scripts[v + 1])         # ファイル内の BEGIN IMMEDIATE … COMMIT が単位
    finally:
        conn.close()

# repo.py（1関数の例。他も同型）
def insert_event(conn, row: NewEvent) -> int:
    cols = [f.name for f in dataclasses.fields(row)]
    sql = f"INSERT INTO events ({', '.join(cols)}) VALUES ({', '.join('?' * len(cols))})"
    cur = conn.execute(sql, [getattr(row, c) for c in cols])
    return cur.lastrowid

# freeze.py
# 関数そのものではなく **名前** を持ち、呼ぶ直前に getattr(queries, …) で解決する。
# import 時に関数オブジェクトを束縛すると T01-27 の monkeypatch が効かない（2026-09-20 実装で確定）。
_OPS = {"question_versions": ("get_question_version", "insert_question_version", NewQuestionVersion),
        "state_versions":    ("get_state_version",    "insert_state_version",    NewStateVersion)}

def freeze_version(conn, *, table, version, text, sha256, now):
    getter, inserter, row_type = _OPS[table]
    for attempt in (1, 2):
        try:
            with transaction(conn):
                row = getter(conn, version)
                if row is None:
                    inserter(conn, row_type(version, text, sha256, now))
                    return ("frozen", sha256, now)
                if row["sha256"] == sha256:
                    return ("already", sha256, row["frozen_at"])
                raise ConfigError(f"{table} {version} は sha256={row['sha256']} で凍結済み。ファイルは {sha256}。"
                                  "版ファイルを変更してはいけない（新しい版を作る）")
        except IntegrityError:
            if attempt == 2:
                raise                                   # UNIQUE 衝突が2回続くのは異常
    raise AssertionError("unreachable")

# queries.py
def current_bundle(conn, bundle_id):
    row = conn.execute("SELECT * FROM bundles WHERE bundle_id = ?", (bundle_id,)).fetchone()
    while row is not None:
        nxt = conn.execute("SELECT * FROM bundles WHERE supersedes_id = ? ORDER BY bundle_id LIMIT 1",
                           (row["bundle_id"],)).fetchone()
        if nxt is None:
            return row
        row = nxt
    return None
```
