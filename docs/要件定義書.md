## 1. 目的・スコープ

本システムは、日本株の適時開示をJev（TypeSafe AI）で判定し、結果が出る前に凍結記録し、後から市場の値動きで採点する個人用のフォワードテスト基盤である。過去データではなく未来のデータで「好材料開示後の数日〜数週間の保有」（PEAD型）に優位性があるかを検証する。

### 目的（優先順）

1. **学習**：Jevのstate・問いの設計、束ね、再較正を実データで習得する。達成はほぼ確実
2. **個人用ツール**：夜間ダイジェスト（開示トリアージ）として使える道具にする。達成確率8割以上
3. **収益検証**：PEAD型戦略がコスト控除後にベースラインを上回るかを確かめる。関門1通過は2〜3割、実弾で再現は1割強と見立てる

### 戦略の確定事項

- **現物のみ**。信用取引・空売りは使わない。損失の最大値は投入額に限定する
- **主戦略：好材料開示の翌朝寄り成行で買い、20営業日後の引けで売る**（PEAD型）。速度不要、張り付き不要
- 秒単位の場中自動売買、寄り付きギャップの逆張り、悪材料の空売りは採用しない

### スコープ内

- TDnet開示の取得、束ね、state構築、Jev判定、凍結ログ、生存監視
- J-Quants日足による事後採点（対TOPIX超過リターン、ベースライン比較、較正）
- 模擬執行（ペーパートレード、8章のルール）
- 夜間ダイジェスト通知と、自分の判断の記録

### スコープ外

- 証券会社APIによる自動発注（関門2通過まで）。段階3は手動発注
- ダッシュボードUI、第三者への公開、シグナル配信
- 製品評判・SNS等のオルタナティブデータ（主検証の結果を見てから判断）
- 日本株以外への汎用化（取得層・採点層を差し替え可能にするに留める）

## 2. 前提とエビデンス

### Playground検証で確認したこと（2026-09-19、52回実行、詳細は検証ログ）

| 項目 | 結果 |
|---|---|
| 方向判定 | up・neutral・downの3方向で妥当。業績予想の修正は上方4件・下方2件とも95%以上で安定、表題の有無に依存しない |
| 織り込み済みの読み分け | 「業績への影響」が数字で明記されていれば中立に置く。続報と新規を区別する |
| 誤判定 | ①同時開示の二重計上（束ねで解消）②買い手と対象者の取り違え（主語固定文で解消）③TOBに無配を束ねると割れる（TOBは束ねの例外） |
| **主語固定文** | directionのinstructionsに「判定対象は発行者 {company}（{code}）自身の株価」と入れるだけで買い手側の誤判定が直る。3ペアで確認、単一当事者では無害。評価軸を入れると誘導になるので入れない |
| impact | 順序付けは機能。絶対値は3クラスタ（≤3.0 / 3.6〜3.7 / 3.85〜4.0）に張り付くので再較正で使う。大型株の構造的事象を過小評価する傾向 |
| routine | 例示に合致すれば機能（70%）。合致しないと低い |
| Confidence | 低い（17〜39%）のは判定に必要な情報がstateにないか、好悪が本当に相殺している場合。問いの設計ミスは検出できない |
| 入力上限 | 5万〜5.5万字の間。4万字超は切り詰め |
| 再現性 | 同一入力で再現（impact ±0.01） |
| 応答時間 | 74〜257ms＋145〜762ms。入力長と無関係 |
| 版 | jev-latest / jev-preview の2択のみ。固定版なし。生レスポンスに版情報があるかは**未確認** |

### 外部の証拠

- PEADは日本市場（東証1・2部、2007〜2018）で有意な正のアルファ。等加重で明確、小型株中心。流動性・サイズで説明できない（大阪大学 DP 2125）
- 決算短信の見通しをLLMでセンチメント化しSUEと掛け合わせると、[+2,+60]営業日の超過リターンとの情報係数が有意に高い（JSAI FIN-035, 2025）。**同じ着想の研究は既にある**
- 同日の発表件数が多いほど反応が遅れ、ドリフトが大きい（証券アナリストジャーナル 2014）
- jev-alpha-bench：ニュース公開当日の相関+0.24、翌日には−0.008。売買可能時点で優位性は消える
- 個人のデイトレーダーで安定して利益を出すのは1%未満（台湾）、300日以上続けた97%が損失（ブラジル）。記憶ベース

### 設計を決めている原則

1. 過去データ検証は使わない（先読み・学習データ汚染・多重検定）。安全なのは2026-09-15以降の未来データのみ
2. Jevは判断者ではなくセンサー。テキストを数値に変える。最終判断は数値特徴量と合わせた再較正・メタモデル、上限はコード
3. 株価は期待との差で動く。前回予想・前期実績をstateに入れなければサプライズは判定できない
4. 問いの設計 ＞ stateの設計 ＞ 情報量。文言はJevの出力を大きく動かすので、問い版を凍結し変更ごとに版を上げる
5. **採点は「翌朝寄り→N営業日引け」で行う**。「前日終値→翌日終値」で採点すると幻の利益（ギャップ）を数える

## 3. 検証設計

### 対象開示（エントリー条件）

すべて事前に固定する。変更時は版を上げ、件数をリセットする。

| 条件 | 値（初版） |
|---|---|
| 開示の種類 | 種類では絞らない。Jev direction = up を満たすもの全て（業績予想の上方修正、増配、大型受注、資本業務提携、**決算短信**を含む。ADR 012）。採点時に `category` と表題で分けて集計する |
| 時間帯 | **引け後開示のみ**：公表時刻が 15:00:00 JST 以降〜翌営業日 8:59:59 JST 以前（`session` = after_close / pre_open）。場中開示（9:00〜15:00）は判定・凍結・採点するが探索扱い（ADR 011） |
| Jevの閾値 | direction up ≥ 80% かつ Confidence ≥ 60% |
| 銘柄 | 普通株。ETF・ETN・REIT・インフラ投資法人・整理監理銘柄・上場後60日未満を除外 |
| 規模 | 時価総額1,000億円未満（PEADは小型株中心） |
| 流動性 | 直近20営業日の平均売買代金 ≥ 1億円 |
| 織り込み度 | 開示前20営業日の対TOPIX超過リターン < +10% |
| 除外事象 | TOB・MBO・株式交換の対象銘柄（株価が対価で決まる） |

### 1件の定義

1件＝凍結済みのJev判定1つ（`purpose='full'`、`model='jev-latest'`、`delayed=0`、エラーなし。ADR 015）× 1銘柄 × 主検証の評価幅1つ。同一銘柄・同一時刻の開示は束ねて1判定（TOB例外）。

評価期間が重なる同一銘柄の判定は独立と見なさず、先の1件のみ数える。手順：銘柄ごとにエントリー日の昇順に並べ、直前に採用した件の終点日（20営業日後）以前にエントリー日が来る件は `overlap_excluded=1` として主検証の件数から外す。外した件も採点はし、探索に使う。

### 評価幅

| 区分 | 起点 | 終点 | 位置づけ |
|---|---|---|---|
| **主検証** | 翌営業日の始値（寄り成行の約定想定） | 20営業日後の終値 | 事前宣言、1つだけ |
| 探索1 | 同上 | 5営業日後の終値 | 探索 |
| 探索2 | 同上 | 60営業日後の終値 | 探索 |
| 探索3 | 翌営業日の始値 | 同日の終値 | 初日の失速（銚子丸型）の測定 |
| 記録のみ | 場中開示の直後に付いた最初の値 | 30分後・当日終値 | 分足が要るため当面は記録のみ |

指標はいずれも対TOPIX超過リターン（TOPIXはJ-Quants指数、またはTOPIX連動ETFの日足で代用）。

### ベースライン（同期間・同条件で並走）

1. ランダム：同じ日に引け後開示があった銘柄のうち、主検証と同じ除外・規模・流動性・織り込み度の条件を満たすものから、同数をランダムに選ぶ。乱数 seed は事前宣言に固定し `outcomes` に記録する
2. ホールド：TOPIX
3. **SUEのみ**：Jevを使わず、営業利益の修正率（業績予想修正）または実績と前回予想の差（決算短信）の上位から、主検証と同数・同条件で選ぶ。**Jevが数値以上の情報を足しているか**を測る最重要ベースライン（ADR 007）。修正率の定義は事前宣言に固定する（task 005）

### 件数と期間

- 600件、最低4週間、上昇・下落局面の両方をまたぐ
- 10月下旬〜11月中旬の中間決算集中期を捕捉する。決算期のみのデータは平時に一般化できないため、平時も並行して蓄積し分けて採点する

### 運用ルール

1. 問い版・stateの書式・エントリー条件・評価幅を開始前に固定し、`config/` に版として保存する。変更したら件数をリセット
2. 主検証を文書で宣言する（`docs/事前宣言.md`）
3. 遅延判定（公表からJev応答まで**300秒超**。ADR 009）はフラグを立て主分析から除外。公表→受信、受信→応答の遅れも別に記録する
4. 停止時間帯が相場と相関していないかを生存ログで事後検証
5. 確率100%/0%は採点時に99.5%/0.5%に丸める
6. 週1回、固定の10件を再判定してimpactの平均差が0.1を超えたら「版の入れ替わり」として警告

### 約定の現実性

- 買いは翌営業日の始値。特別買い気配で寄らない場合は約定なし（当日中に付いた最初の値で約定とする案は探索用）
- 売りは終値。ストップ安張り付きは翌日に繰り越す
- コスト：手数料0.1%（往復）、スリッページ0.2%、を初版とする

### 判定基準

- **通過**：主検証で、コスト控除後の平均超過リターンがランダム・ホールド・SUEのみの3つすべてを有意に上回る
- **検定方法**（ADR 013）：エントリー日を1ブロックとする日別ブロック・ブートストラップ。ブロックを復元抽出して平均差を10,000回再計算し、差の両側95%区間の下限が0を上回れば有意。seed は事前宣言に固定。週ブロックを感度分析、ポートフォリオ日次リターンの t 検定を探索として併記する。単純な t 検定は使わない（同日・重なり期間の依存で甘くなる）
- **撤退**：600件で有意差なし。収益目的は打ち切り、開示トリアージと自社業務への転用に切り替える

## 4. システム構成

### 実行環境（v2で変更：VPS主・NAS副）

| 環境 | 役割 | 理由 |
|---|---|---|
| **VPS**（1vCPU・1GB、月500〜1,000円） | 取得・束ね・判定・凍結ログ・監視・ダイジェスト通知の常時稼働 | 自宅回線の不安定さから切り離す。データセンターの回線と電源 |
| **NAS（DS220+）** | VPSのSQLiteの日次バックアップ先。凍結ログは再生成できない | NASの得意分野。自宅回線が落ちてもVPS側は止まらない |
| ローカルPC | 開発、採点、分析、レポート | J-Quants日足は後から取れるので、採点は非同期でよい |

### レイヤー

```
TDnet ─▶ 1 取得 ─▶ 2 束ね/フィルタ ─▶ 3 state構築 ─▶ 4 Jev判定 ─▶ 5 凍結ログ(SQLite, 追記専用)
                                                                   │
J-Quants日足 ─▶ 6 採点(ローカル) ◀────────────────────────────────┘
                     │
                     ▼
              7 模擬執行 / 8 週次レポート          9 監視・ダイジェスト通知(VPS)
```

### 設計原則

- 取得層と採点層は差し替え可能。判定・凍結・監視は共通
- 執行層はインターフェースを切り、模擬→手動→（将来）APIに差し替え可能
- VPSは外向き通信のみ。APIキーは環境変数
- 将来の実弾でも建玉の安全（逆指値）はシステムの稼働に依存させない

## 5. 機能要件

| ID | 層 | 要件 | 優先度 |
|---|---|---|---|
| F1-1 | 取得 | TDnet新着一覧を1分間隔で取得し、公表時刻・コード・社名・表題・PDF URLを保存。一覧取得はPDF取得と分離し、一覧が取れればPDF失敗時も表題で暫定判定する | 必須 |
| F1-2 | 取得 | PDFをテキスト化（PyMuPDF）。XBRLがあれば数値も取得 | 必須 |
| F1-3 | 束ね | 同一銘柄・同一時刻（±5分）の開示を1出来事に束ねる。**重複排除はPDFのSHA-256**（同一表題でも別契約がある）。連番表題（（１／３）等）は束ねる。**TOB・MBO・株式交換は束ねず意見表明を単独判定し、付随開示に「TOB付随」フラグ** | 必須 |
| F1-4 | フィルタ | 除外（判定しない）：ETF・ETN（E-、N-、コード末尾4等）、REIT（R-）、インフラ投資法人（I-）、整理・監理銘柄、上場後60日未満、除外表題（約款変更、ETFの分配金、日々の開示事項）。重要度低下（判定するがダイジェストから外す、`flags_json` に記録）：事業計画及び成長可能性、CG報告書改定（ADR 019） | 必須 |
| F2-1 | state | 発行者名・コード・役割、直前終値、時価総額、市場区分、直近20日リターンを付加 | 必須 |
| F2-2 | state | 直近30日の同社開示の表題一覧、同時刻の他開示の表題一覧を付加 | 必須 |
| F2-3 | state | 前回予想・前期実績（XBRL）を付加し、サプライズ度の計算材料にする | 必須（段階2開始まで。ADR 012） |
| F2-6 | state | VPS 上の `market_cache` プロセスが平日 06:30 JST に J-Quants から前営業日の日足・銘柄一覧・TOPIX を取得し、F2-1 の材料を用意する。取れない項目は null で進み `state_completeness` に記録（ADR 017） | 高 |
| F2-4 | state | 本文が4万字を超えたら切り詰め：主開示の先頭優先、報告書型は目次から「原因・評価・結論」章の冒頭を追加。束ねは主＋副2件の全文＋残りは表題 | 必須 |
| F2-5 | state | state書式に版番号 | 必須 |
| F3-1 | 判定 | 問い版v2（6章）を1回のリクエストで投げ、全回答・確率・Confidenceを保存 | 必須 |
| F3-2 | 判定 | jev-latestとjev-previewの両方に投げて両方記録（版の入れ替わり検知） | 高 |
| F3-3 | 判定 | タイムアウト・リトライ・エラー種別（max_tokens_exceeded等）と入力文字数を記録 | 必須 |
| F3-4 | 判定 | 生リクエスト・生レスポンスをそのまま保存。版情報の項目があれば抽出 | 必須 |
| F3-5 | 判定 | 判定の目的区分 `purpose`（full / provisional / recheck）を記録。表題のみの暫定判定は provisional、PDF到着後に full を追加、週次再判定は recheck。主分析は full のみ（ADR 015） | 必須 |
| F3-6 | 判定 | 問い版は `question_versions` に凍結済みのものだけ使える。凍結は CLI `freeze-questions`（ADR 020） | 必須 |
| F4-1 | 凍結 | 追記専用。UPDATE/DELETE をアプリ層で禁止し、DB 層でも BEFORE UPDATE/DELETE トリガーで拒否する（ADR 014） | 必須 |
| F4-2 | 凍結 | 公表時刻・受信時刻・Jev応答時刻をUTCで記録 | 必須 |
| F4-3 | 凍結 | 遅延判定フラグ（公表からJev応答まで300秒超）。公表→受信 `fetch_lag_sec`、受信→応答 `process_lag_sec` も記録（ADR 009） | 必須 |
| F4-4 | 凍結 | 束ねに `session`（after_close / intraday / pre_open）と `flags_json`（重要度低下・切り詰め・暫定のみ等）を記録（ADR 011, 019） | 必須 |
| F5-1 | 採点 | J-Quants日足で評価幅ごとの対TOPIX超過リターンを計算（寄り→引け） | 高 |
| F5-2 | 採点 | 特別気配・ストップ・コストを反映 | 高 |
| F5-3 | 採点 | ランダム・ホールド・SUEのみの3ベースライン | 高 |
| F5-4 | 採点 | 較正曲線と再較正表。100%/0%は丸める | 高 |
| F5-5 | 採点 | 数値特徴量（ギャップ率、出来高倍率、事前リターン、同日発表件数、時価総額）とJev出力を並べた特徴量テーブルを出力 | 高 |
| F6-1 | 模擬執行 | エントリー条件を満たす判定から翌朝寄りの模擬注文を生成し、8章の出口ルールで決済 | 中 |

### 問い版 v2（`config/questions.v2.json`）

| ID | 型 | 問い | 用途 |
|---|---|---|---|
| direction | Choice（up/down/neutral） | 主語固定文＋「開示直後の株価の反応は市場平均と比べてどうなるか」。criteriaに「公開買付けの対象銘柄は買付価格と直前株価の比較で判断」を追加 | 主検証のエントリー |
| impact | Score 0〜4 | 主語固定文＋影響の大きさ。基準に修正率の目安を数字で入れ、技術的・形式的変更は除外と明記 | 閾値、再較正 |
| routine | Noul | 定型か。例示を拡充（公表済み枠の執行通知、勧告と同額の決定、連結移行に伴う予想置き換え、定款の形式的変更、事務手続きの案内、約款変更）。続報でも期日の遅延や体制変更を含めば新情報 | 除外 |
| surprise | Score 0〜4 | 前回予想・前期実績に対するサプライズ度。「前回予想が保守的だっただけ」を区別 | PEADの核 |
| transient | Noul | 一過性の要因か（補助金、為替、特別利益） | 持続性 |
| conditional | Noul | 条件付きの決定か（TOB成立条件など） | TOB付随の識別 |
| category | Choice | 決算・業績修正・配当・自己株・M&A・資本政策・不祥事・その他 | カテゴリ別成績 |

## 8. リスク制御（模擬段階から実装、実弾でも同一）

### 建玉

- 現物のみ。1銘柄は資金の5%、同時保有は最大10銘柄（資金の半分は常に現金）
- 段階3の投入資金は50〜100万円を上限（全額失っても生活に影響しない額）

### 出口ルール

| 出口 | ルール | 理由 |
|---|---|---|
| **時間切れ（主）** | 20営業日目の引けで無条件に売る | PEADは時間で消える。裁量を排除 |
| 損切り | 建値から△8%で成行。実弾では発注時に逆指値を証券会社側へ置く | 資金の0.4%の損失。小型株の日中変動を考慮 |
| 前提の崩壊 | 保有中に下方修正・不祥事・監理指定が出たら翌朝売る | ロガーが検知 |
| 初日の失速（探索） | 初日終値<寄り値なら翌朝売る。**初版では採用せず記録のみ** | 600件で有効性を見てから |
| 利確 | しない | 利益は右裾に集中する |

### しないこと

ナンピン、買い増し、地合いによる裁量の見送り、含み益での利確、損切りの先延ばし、問いの途中変更。

### 停止

生存ログ途絶・エラー率上昇で新規停止。スマホから手動停止。1日の新規は最大3銘柄。

### 既知のリスク

| リスク | 対応 |
|---|---|
