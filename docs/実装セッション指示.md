## セッション2：M2（取得と監視）

```
M1が完了しています。CLAUDE.md と docs/基本設計書.md 3.1・3.6 を読んでから、M2を実装してください：

1. src/jevfwd/fetch/tdnet_list.py：TDnet新着一覧の取得。取得方法は【ここに段階0で確認した方法を書く：公開ページのHTML解析 / 有料API】。1分周期で差分を取り、(公表時刻, コード, 表題) で既知判定。tests/fixtures/tdnet_list_2026-09-17.tsv を解析できること（TSV形式はTDnetの表をコピーしたもの。列：時刻、コード、会社名、表題、XBRL、上場取引所、更新履歴）
2. src/jevfwd/fetch/tdnet_pdf.py：PDF取得（httpx、3回リトライ）、SHA-256、PyMuPDFでテキスト化、scan_suspect判定。scripts/pdf2txt.py のロジックを移植してよい
3. events への追記。PDF取得に失敗しても一覧の行は pdf_status='failed' で登録する
4. src/jevfwd/monitor/heartbeat.py と notify.py（ntfy）。60秒ごとに1行、直近3行欠落で通知
5. cli の fetch と heartbeat を実装。`fetch --once` で1回だけ実行できること

TDnetへのアクセス頻度は1分に1回以下。並列ダウンロードはしない。利用規約に反する疑いがあれば実装前に指摘してください。
```

## セッション4：M4（判定）

```
M3まで完了。docs/基本設計書.md 3.4・3.5 を読んでからM4を実装してください：

1. src/jevfwd/judge/client.py：POST https://api.typesafe.ai/v1/systemone。TYPESAFE_API_KEY は環境変数。timeout 10秒、指数バックオフで3回リトライ。jev-latest と jev-preview の両方に投げる。エラー（max_tokens_exceeded 含む）も judgments に行を残す。生レスポンスをそのまま保存し、版情報らしき項目があれば model_version に抽出
2. judge_worker：キューから bundle を取り、state構築→判定→judgments/answers 追記。公表から60秒超なら delayed=1
3. テストはクライアントをモック。実APIの呼び出しは `judge --once --bundle <id>` を私が手で1件実行して確認する
4. 日次コストの概算（入力文字数×係数）を heartbeat に記録し、settings.yaml の上限超過で新規判定を停止

実APIを叩く前に、リクエストJSONを1件 stdout に出して私に見せてください。
```
