# 016: events は1PDF=1行、連番表題の結合は bundle 層

- Status: Accepted
- Date: 2026-09-20
- Related: 要件F1-3、基本設計3.1・3.2、ADR 004

## Context
基本設計3.1は events を1PDF=1行（`pdf_sha256 UNIQUE`）としつつ、3.2は「連番表題（（１／３）等）は同一eventとして結合」としており矛盾していた。中部電力の調査報告書は3分割PDFで、束ねると28万字になる。

## Decision
- `events` は1PDF=1行のまま。連番表題の各PDFは別 event
- 連番の結合は bundle 層で行う。`grouper` は同一コード・同時刻で表題の連番部分（`（１／３）` `(1/3)` `【1】` 等、パターンは `filters.v1.yaml` の `sequence_patterns`）を除いた表題が一致する events を1つの「論理開示」として扱い、主開示選定では1件として数える
- state 構築時に本文を連番順に連結する。連結後の文字数が切り詰め対象になる
- `bundles.event_ids_json` に全 event を、`bundles.logical_docs_json` に論理開示ごとの event_id 配列と結合後表題を持つ

## Alternatives
- fetcher で結合して1 event に：PDFハッシュによる重複排除（ADR 004）と衝突する。一覧の差分取得でも連番は別行で来る

## Consequences
- 中部電力3分割は `tests/fixtures/9502_chubu_report_full.txt` が結合済み本文。テストは3分割の表題行から論理開示1件になることと、連結順序を確認する
