# 010: ダイジェストは18:30速報便と07:30確定便の2便

- Status: Accepted
- Date: 2026-09-20
- Related: 要件F8-1、7章「稼働 24時間（23:45の開示あり）」、基本設計1章・3.7

## Context
基本設計はダイジェストを平日18:30 JSTの1便としていた。TDnetの開示は23:45まであり、18:30以降の開示（決算集中日には少なくない）は翌朝の寄り注文に乗らず、次の翌朝まで1営業日遅れる。PEADの初日を捨てることになり、採点上も不利。

## Decision
- **18:30便（速報）**：当日15:00以降〜18:30の候補を通知。夜のうちに目を通す用
- **07:30便（確定）**：前営業日15:00以降〜当日07:30の候補をすべて含めて通知。翌朝の注文の最終判断はこの便で行う。18:30便に含まれた件も再掲する（1通で完結させる）
- 1日の新規上限3銘柄は07:30便の候補一覧に対して適用する。候補が3件を超える場合は up 確率 × impact の降順で上位3件を注文案とし、残りは「候補外」として同じ通知に列挙する
- 時刻は `config/settings.yaml` の `digest.runs` から読む

## Alternatives
- 07:30便のみ：夜間に予習する時間がなくなる。運用は単純だが手動発注段階（段階3）で朝の判断時間が短い
- 18:30便のまま夜間開示は翌々朝：PEADの初日を捨てる。却下

## Consequences
- digest プロセスは1日2回起動。休日・祝日は東証の営業日カレンダーで判定（J-Quants の営業日情報、または固定の祝日表）
- `my_calls` の「買う／見送る」記録は07:30便に対して行う
- 場中開示（9:00〜15:00）は両便に含めない（ADR 011）
