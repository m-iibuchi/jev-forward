# 019: 除外と重要度低下を分け、低下は flags_json で表す

- Status: Accepted
- Date: 2026-09-20
- Related: 要件F1-4、基本設計3.2・5章、検証ログ #19, #20, #21

## Context
要件F1-4 は「除外」（ETF・ETN・REIT・インフラ投資法人・整理監理銘柄・上場後60日未満）と「重要度を下げる」（事業計画及び成長可能性、CG報告書改定、約款変更、日々の開示事項）を並べていたが、後者を判定するのか、ダイジェストに出すのか、主検証に含めるのかが曖昧だった。`bundle_role` は normal / tob_primary / tob_attached / excluded の4値で、重要度低下を表せない。

## Decision
- **除外**：判定しない。`bundle_role='excluded'`、`skip_reason` に理由（`excluded_instrument` / `excluded_supervised` / `excluded_new_listing` / `excluded_title`）。凍結ログには残す
- **重要度低下**：判定する。`bundle_role='normal'` のまま `bundles.flags_json` に `["low_priority:growth_plan"]` のようにフラグを付ける。ダイジェストから外す。主検証には含める（エントリー条件を満たすなら対象。Jevが正しく低 impact を出すかの検証にもなる）
- 除外の表題パターン（例：投資信託約款の変更、ETFの収益分配金）は `filters.v1.yaml` の `exclude_titles`、低下は `low_priority_titles` に分ける

## Alternatives
- 低下も除外に：Jevの routine / impact が機能しているかを実データで測る機会を失う
- bundle_role に low_priority を追加：TOB との組み合わせ（tob_attached かつ low_priority）を表せない

## Consequences
- `flags_json` は文字列配列。将来 `scan_suspect` `truncated` `provisional_only` などもここに入れる
- 採点では flags 別の成績も探索として出す
