# 025: 営業日カレンダーは版付き設定ファイルに持ち、settings が読む

- Status: Accepted
- Date: 2026-09-20
- Related: ADR 011、task 011、詳細設計 04-束ね 3.3・4.10・4.13、00-共通規約 8章

## Context
ADR 011 の `session` 判定は「休日は after_close」を含むが、営業日判定の実体が決まっていなかった（task 011）。当面は土日だけを休みとする案もあったが、

- `bundles.session` は**追記専用**の列で、主検証の母集団（`docs/事前宣言.md`）を定義する。祝日を `intraday` と誤記録すると、後から直すには superseding bundle を作るしかない
- 運用開始直後に 2026-09-21（敬老の日）、09-22（国民の休日）、09-23（秋分の日）が並ぶ。平日扱いなら 10:00 の開示が `intraday` になり、本来 `after_close` として主検証に入るべき件を落とす

置き場も決める必要があった。カレンダーは `bundle`（session）だけでなく `state`（直前終値の基準日）`score`（N営業日）`digest`（2便の対象日）も使うが、モジュール境界（00-共通規約 8章）では `bundle` から `market` を import できず、`common` は外部ライブラリ（pyyaml）を import できない。

## Decision
- `config/trading_calendar.vN.yaml`（版付き、作成後は不変、SHA-256 をテストで固定）に休業日と半日立会を持つ
- 読み手は `settings.py`（`Calendar` と `load_calendar`）。全モジュールが `settings` を import してよいので境界を変えずに済む。`Filters` が純関数のヘルパを持つのと同じ扱い
- `Calendar` は `is_business_day` `close_time` `next_business_day` `prev_business_day` を持つ。収録年の外を問われたら `ConfigError`（黙って平日扱いにしない）
- `settings.yaml` に `calendar_version`（既定 v1）を足す
- v1 の中身（2026・2027）は国民の祝日＋年末年始から作った**暫定値**。JPX の休業日一覧との突合は人が行う（task 011 は `in_progress` のまま、段階2開始前に確定）

## Alternatives
- 土日だけの実装で段階1を回す：上記のとおり `session` を永久に誤らせる。却下
- `common/calendar.py`：`common` が pyyaml を import することになる（00-共通規約 2章に反する）。JSON にすれば回避できるが、設定ファイルの読み手を `settings.py` に一本化している方針と食い違う
- J-Quants の営業日 API を実行時に引く：段階1は `market_cache` を無効にしている。ネットワーク依存を `session` 判定に持ち込まない。M6 で取得して v2 の作成に使うのはよい

## Consequences
- `Calendar` は `bundle` `state` `score` `digest` が引数で受け取る（`datetime.now` と同じく、外から渡してテストで差し替える）
- 半日立会（`half_days`）があれば `close_time` がそれを返し、`session` の閾値が変わる
- 収録年を跨ぐ前に v2 を作る必要がある。起動時に「今日と翌30日が収録されているか」を検査する
