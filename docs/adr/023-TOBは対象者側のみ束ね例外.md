# 023: TOB の束ね例外は対象者側だけに適用する

- Status: Accepted
- Date: 2026-09-20
- Related: ADR 003（補足）、詳細設計 04-束ね 4.7、`config/filters.v1.yaml`、検証ログ #11b, 26a/26b

## Context
ADR 003 は「表題に『公開買付』『ＭＢＯ』『MBO』『株式交換』を含む開示があれば、その開示を単独 bundle（`tob_primary`）にし、同時刻の他開示を `tob_attached`（主検証から除外）にする」と決めた。根拠は「**対象銘柄**の株価は買付価格でほぼ決まるので、同時刻の悪材料は効かないのに Jev は字面に引かれる」（レオパレス 26a/26b）。

fixture を見ると、この表題パターンは対象者側以外も拾う。

- `tdnet_list_2026-09-17.tsv` 80行目 `68900 フェローテック`「株式会社日本抵抗器製作所（証券コード：6977）に対する公開買付けの開始に関するお知らせ」＝**買付者側**。買付者の株価は買付価格で決まらない。ADR 003 の根拠が当てはまらないのに主検証から落ちる
- 同 30行目 `44360 Ｇ－ミンカブ`「公開買付けに準ずる行為として政令で定める買い集め行為に関するお知らせ」。同時刻8件の中の1件で、これが TOB と判定されると本命の「NTTデータ、SBIグループとの資本業務提携」が `tob_attached` に落ちて主検証から消える
- 同 177行目 カカクコム「『…公開買付けの開始予定に関するお知らせ』の一部変更に関するお知らせ」も同種の誤検知

## Decision
- `filters.v1.yaml` に `tob_target_titles`（「当社株券等に対する公開買付」「当社株式に対する公開買付」「賛同の意見表明」「賛同の表明」「応募推奨」）と `tob_exclude_titles`（「準ずる行為」「一部変更に関するお知らせ$」）を足す
- **対象者側**に一致したときだけ ADR 003 の束ね例外（`tob_primary` ＋ `tob_attached`）を適用する
- `tob_titles` に一致するが対象者側でないもの（買付者側）は通常どおり束ね、`bundle_role='normal'` のまま `flags_json` に `tob_buyer` を付ける。採点では `tob_buyer` 別の集計を探索として出す
- `tob_exclude_titles` に一致したら TOB として扱わない

## Alternatives
- ADR 003 のまま（表題に一致したら全部例外）：買付者側の M&A 開示を主検証から落とす。フェローテック・光通信のような「買い手にとっては純粋な投資判断材料」を捨てることになる
- 買付者側も `tob_attached` にする：同上。加えて「TOB 付随」の意味が2種類に増える
- 発行者コードと表題中の証券コードを突き合わせて機械判定する：表題に対象会社のコードが無い開示（レオパレスの意見表明）があるため単独では成立しない。表題パターンと併用するなら将来の改善案

## Consequences
- ADR 003 の Decision は生きているが、適用範囲が「対象者側」に狭まる（ADR 003 を置き換えない補足）
- 誤検知パターンは版管理された `filters.vN.yaml` にあるので、漏れが見つかったら新版で直す（既存の判定結果は作り直さない）
- 買付者側は `normal` なので主検証の母集団に入る。`docs/事前宣言.md` の母集団の説明に `tob_buyer` の扱いを1行足す
